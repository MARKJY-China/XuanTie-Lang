# 铸造厂 UI 设计器 —— 设计区格式规范 v1

对标：玄铁 UI 库 v1.5.3 / 渲染库 v1.3.1（本版以该组合的实编译探针验证，见 §5）

本规范是"可视化 UI 设计器"（铸造厂 IDE 内）与玄铁源码之间**唯一约定的接口**：
设计器只读写源文件中被标记包裹的一段"设计区"，区外内容一个字节都不动。
机器可读常量见 `ide/src/ui/designer/spec.ts`（两边改动须同步）。

## 1. 设计区标记

```
// ===== 铸造厂·设计区 开始:<名字> =====
// (本区由设计器维护;手工改动仅限属性值;非子集写法将导致本区只读)
函 <名字>(<状态>) {
    …（见 §2 子集）…
}
// ===== 铸造厂·设计区 结束:<名字> =====
```

- 一个文件可有多个设计区；**一个区一个界面**（区内除构建函外不允许其它内容）。
- 开始/结束标记必须成对同名；未闭合的开始标记被忽略（不完整区间不可安全改写）。
- 区外的任何代码（其它函数、`造状态`、事件处理函、`应用` 调用等）自由书写，与设计区混合在同一文件——这正是"无独立 UI 文件"约束下的落地形态（等价于易语言把窗体定义写进源文件）。
- **拆文件选项**：区可整体搬到独立文件（如 `主界面.界面.xt`），逻辑文件 `引 "主界面.界面.xt" 予 界面` 后使用 `界面.主界面`——解析器/生成器无需任何改动。

## 2. 子集语法

```
design     := '函' <名字> '(' <状态> ')' '{' { decl } '返' <根名> '}'
decl       := '设' <容器名> '=' call
call       := 'UI' '.' <控件名> '(' 参数表 ')'
参数表     := 按 §4 控件形态表：位置实参（字面量/态取/色彩/名字）+ children 数组 + 选项字典（恒在末位）
children   := '[' { 叶子调用 | <已 设 的容器名> } ']'
选项字典   := '{' { (字符串键 | 裸标识符键) ':' 值 } '}'
```

- 容器（行/列/叠/绝对/滚动容器）必须以 `设 <名> = …` 命名后再被引用；叶子控件直接内联在 children 里。
- 数组与字典**不允许尾随逗号**（编译器硬约束；实测报"不支持的前缀类型: 右方括号"）。
- 一个区内不允许死代码（声明后未被引用则判非子集）。

## 3. 值白名单

| 形态 | 例 | 说明 |
|---|---|---|
| 字面量 | `"开始"`、`120`、`1.5`、`真` | 字符串保留源转义原文 |
| 状态绑定 | `UI.态取(s, "标题")` | 状态键必须是字符串字面量 |
| 颜色常量 | `UI.色彩["主题"]` | 键必须是字符串字面量 |
| 具名引用 | `开始点击`、`界面模块.处理点击` | 只用于回调槽；函体写在区外的逻辑区 |

**刻意不含**：表达式、运算符、`若`/`遍历`、内联闭包（`函() {…}`）。
理由：设计器必须能把文本**完整往返**（解析→编辑→生成），受限子集让往返不可能产生歧义；
上述写法一次归零，全部改为"状态驱动"（`态取` + 逻辑区改状态）——这与 UI 库的每帧重建模型天然契合。
命名的引用允许**跨模块**（`模块.名字`），已实测编译通过——这是拆文件方案成立的依据。

## 4. 控件形态表（UI 库 14 构造器）

| 形态 | 控件 | 参数 |
|---|---|---|
| 容器 | 行 / 列 / 叠 / 绝对 / 滚动容器 | `children, 选项` |
| 叶子 | 文本 / 按钮 | `值, 选项` |
| 叶子 | 矩形 | `选项` |
| 叶子 | 图片 / 图标按钮 | `源, 选项` |
| 叶子 | 输入栏 / 多行编辑 | `状态, 键, 选项` |
| 叶子 | 空白 | `选项` |
| 叶子 | 弹性 | `数, 选项` |

选项键共 41 个（几何 / 视觉 / 三态覆写 / 行为四组），逐键文档见 `GUIDE/UI/选项键/`。
生成器按 `spec.ts` 的 `KEY_ORDER` 规范序排序键，保证同一棵树恒产出同一字节。

## 5. 生成器硬规矩（全部有实测背书）

1. **无尾随逗号**（探针实测：带逗号的数组字面量编译器直接拒绝）；
2. 键按规范序、键一律双引号；
3. 每叶子控件一行、每容器一条 `设` 语句（post-order：子容器先写，最后 `返 根`）；
4. 缩进 4 空格；children 非空即多行（每项一行）；
5. 同一棵树恒产出同一字节（往返幂等）。
6. 具名函作回调值（`"点击": 开始点击`）与跨模块引用（`"点击": 模块.开始点击`）——均已 `-jc` 实测通过。

## 6. 非子集 → 只读

设计区若含子集外内容（上表任一红线：表达式、内联闭包、未知控件、尾随逗号、成环引用、
死代码、叶子被 `设` 命名等），解析器给出**逐条带行号的原因**，设计器把该区切为**只读**：
可以看，绝不改写。这保证"设计器永远不会破坏它看不懂的代码"。

## 7. 完整示例（实编译通过的形态）

```xuantie
// ===== 铸造厂·设计区 开始:主界面 =====
// (本区由设计器维护;手工改动仅限属性值;非子集写法将导致本区只读)
函 主界面(s) {
    设 左栏 = UI.列([
        UI.文本(UI.态取(s, "标题"), {"字色": UI.色彩["主题"], "字号": 24}),
        UI.按钮("开始", {"宽": 120, "高": 40, "点击": 开始点击})
    ], {"弹性": 1})
    设 根 = UI.行([左栏], {"宽": 800, "高": 560})
    返 根
}
// ===== 铸造厂·设计区 结束:主界面 =====

函 开始点击() {          // 逻辑区:设计器双击控件时在此生成/跳转
    // …
}
```

## 8. 验收标准（切片 1 已达成）

1. 往返幂等：解析→生成→再解析语义等价，二次生成逐字节一致 ✅
2. 区外零改动：任意操作后仅标记区间变化（含 CRLF/LF 行尾保持）✅
3. 非子集 11 类样例全部判只读并给出原因 ✅
4. 产物可编译：示例形态经 `-jc` 实编译通过 ✅
5. 单测：`ide` 下 `npm run test:designer`（esbuild+node，零新增依赖）22/22 通过 ✅

## 9. 版本演进约定

- 控件形态表 / 选项键规范序 / 标记格式的**任何改动**，必须同步 `spec.ts`、本规范与单测三方；
- 新增控件 = 先在 UI 库落地 → 更新本表与 `spec.ts` → 设计器工具箱自动获得；
- 规范版本号随本文件标题递增（v1 → v2 …），并记录在提交信息中。
