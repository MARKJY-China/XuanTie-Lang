# 会话日志（会话之间的记忆）

> 规则见根 `AGENTS.md` 的 `Ecosystem Sync Across Sessions` 段。**每次会话收工前写一条**。

## 为什么

对话无法跨会话传递，文件可以。新会话开工时读最近 3 条，就能知道"上一个会话为什么这么设计、踩了什么坑"，不必从零猜测。

## 命名

```text
docs/sessions/YYYY-MM-DD-主题.md
例：2026-10-17-渲染库v1.3.3与W007.md
```

同一天多条时加序号：`2026-10-17-2-设置对话框下拉替换.md`。

## 模板

```markdown
# YYYY-MM-DD 主题

## 做了什么
- （最多 5 条，一句话一条）

## 改了哪些对外接口
- 无 / 或：接口名（文件）→ 从什么改成什么 → 依赖方需要做什么
- ⚠ 未同步：若改了别的仓库依赖的接口但没更新 docs/contracts/，必须写在这里

## 踩了什么坑
- 现象 → 根因 → 规避方式（最多 3 条）

## 下一步待办
- （最多 5 条，标出需要用户拍板的）
```

## 硬约束

- **只写事实**：改了什么、验证到什么程度（跑过哪些命令、结果如何）。推测要标"推测"。
- **不要重复 commit message 的正文**：这里写的是思路、坑和交接，不是变更清单。
- 会话结束时若还有未完成的大块工作，写清"卡在哪、下一步从哪接手"。
