# 插件图标格式转换与替换记录

本文记录 VSCode 插件（extensions/xuantie-syntax）图标从旧版书法「玄」字替换为 `assets/玄铁logo-玄印.svg` 新版 logo 的完整流程。源与目标：

- 源：`assets/玄铁logo-玄印.svg`（官方印章式 logo，viewBox 120×120，圆角矩形 + 线段字形）
- 反色配方：背景 `#B03A2B` → `#F4EEE2`（品牌米），字形 `#F4EEE2` → `#16120C`（黑，取自设计稿实测最深色）
- 目标：`extensions/xuantie-syntax/icon.png`（512×512，透明圆角）+ `icon.ico`（128×128 PNG-in-ICO）

## 一、SVG 反色

直接改 SVG 的两个颜色值：rect 的 `fill="#B03A2B"` → `#F4EEE2`；`color="#F4EEE2"` → `#16120C`。存为临时 SVG 即可渲染。

## 二、栅格化（纯 Python，零依赖）

玄印 SVG 仅含圆角矩形 / 线段 / 方块，用距离场直接栅格化即可，无需外部渲染器：

- 512×512 画布，2× 超采样抗锯齿；全画布 RGBA 起始全透明（圆角外保持透明，图标自带圆角）；
- 圆角矩形判定用标准 SDF：`hypot(max(qx-hx, 0), max(qy-hy, 0)) ≤ rad`，其中 hx/hy 为半宽高减半径——初版误用 `max(qx-hx, qy-hy) ≤ 0` 判定，会漏画四条直边带（渲染出十字形空痕）；
- 线段沿线以 0.5px 步进刷软边圆刷；所有坐标乘缩放系数（SVG 单位 → 像素），漏乘会把字形缩在画布一角。

避坑：`qlmanage -t` 渲 SVG 实测会卡死不返回，勿用；`sips -s format ico` 接受参数并打印路径但**实测不产出文件**，ico 需手工封装。

## 三、icon.ico 手工封装

ICO 容器手工构造：6 字节头（保留 0 / 类型 1 / 条目数 1）+ 16 字节目录项（宽 128、高 128、颜色 0、保留 0、平面 1、位深 32、数据长度、数据偏移 22）+ 原样内嵌 128×128 PNG。PNG-in-ICO 条目 Windows Vista 起全支持，VSCode 读取正常。

## 四、替换点与同步

- `extensions/xuantie-syntax/icon.png` / `icon.ico`：直接覆盖（package.json 的 icon 与 languages[].icon 引用路径不变）；
- JoyCode 安装副本：`~/.joycode-editor/extensions/xuantie.xuantie-syntax-2.3.4/` 同名覆盖，重载窗口生效；
- VSIX 重打包：`server/xt_lsp` 需先在**编译器包目录内**现场重编（链接命令含 `runtime/` 相对路径，从别处跑必失败），且 `server/` 目录不存在时链接器直接失败，先建目录——两坑 build.ps1 内有注，手工打包同样要防。

## 五、验证

JoyCode（京东魔改 VSCode，macOS arm64）重载后：扩展面板图标与 .xt 文件图标均为新版玄印 logo；LSP 诊断（现场重编的 server/xt_lsp）不受影响。
