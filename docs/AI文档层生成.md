# AI 文档层生成（all.txt / index.json）

> 对标编译器版本：v1.0-rc.3 ｜ 生成器：`tools/gen-ai-docs.mjs`

## 为什么有这一层

issue #118：文档站 `/ai/all.txt` 曾与实现漂移近一个月——AI 按文档写代码，运行到才报错（典型：`字典.键集`）。根因不在内容，而在**产物没有"可信度信息"**：读者无法判断手上的 all.txt 对应哪个版本、哪些条目已经实现。

现在生成器把两件事写死进产物：

1. **页头**：生成日期 + 对应编译器版本（版本号从 `xuantie_compiler/玄铁.xt` 的 `版本号` 常量读取，不手写）；
2. **逐文件/逐 API 状态**：默认「已实现」，例外集中在 `tools/ai-doc-status.json`。

## 用法

```bash
# 1) 先生成 API 参考（可选，GUIDE/API 不存在时 AI 层会少这部分）
node tools/gen-api.mjs

# 2) 生成 AI 文档层（默认输出 dist/ai-docs/）
node tools/gen-ai-docs.mjs
```

产物：

| 文件 | 用途 |
|---|---|
| `all.txt` | 全部文档拼接的纯文本，页头带日期/版本，每篇带状态行，API 标题下带状态标注 |
| `index.json` | 机器可读索引：每篇路径、状态、字节数，以及生成日期与版本 |
| `llms.txt` | 给 AI 抓取的入口说明 |

## 维护状态标注

编辑 `tools/ai-doc-status.json`：

```json
{
  "默认状态": "已实现",
  "文件例外": {
    "GUIDE/关键字/字典.md": { "状态": "部分超前", "说明": "「键集」实现缺失（issue #112）" }
  },
  "函数例外": {
    "R.截图": { "状态": "已变更", "说明": "v1.3.7 起为请求式" }
  }
}
```

- 修好一个漂移项就把它从例外里删掉——状态表本身就是"还欠哪些"的清单；
- 每篇的状态同时写进 `index.json`，AI 可以只读索引快速判断可信度。

## 发布纪律（建议）

发版时按顺序执行：`gen-api` → `gen-ai-docs` → 部署站点。all.txt 的页头日期应与本次发版日期一致；若站点上的 all.txt 日期落后于发行包，说明该次发布漏了这一步。
