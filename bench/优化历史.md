## ✅ 已修复回归：除/模被整条改道（2026-09-27 定位并修复）

把 2026-08-15 历史表回填后与本次实测对照，发现两项显著变慢。为排除机器与口径差异，用**同一台机器、同一份语料、8 月 16 日的旧编译器**（`build/xtc_prev.exe`）做了对照：

| 用例 | 2026-08-15 历史表 | 2026-08-16 编译器(本机复测) | 当前链顶(本机) | 变化 |
|---|---|---|---|---|
| 乘模1e6 | 19,320 µs | 17,713 ~ 18,445 µs | 121,268 ~ 126,556 µs | **慢约 6.8×** |
| 分支1e7 | 252,965 µs | 232,482 ~ 245,266 µs | 1,304,536 ~ 1,313,687 µs | **慢约 5.5×** |
| 空函数调用1e6 | 5,944 µs | 5,054 ~ 14,460 µs(抖动大) | 8,286 µs | 噪声范围内 |
| fib30 递归 | 25,021 µs | — | 23,204 µs | 略好 |
| 字符串拼接1e5 | 3,514 µs | — | 3,205 µs | 略好 |
| 列表添加1e5 | 6,667 µs | — | 3,957 µs | 更好 |
| 字典插入1e4 | 48,631 µs | — | 30,471 µs | 更好 |
| 浮点累加1e6 | 255,203 µs | 256,626 ~ 262,416 µs | 264,325 µs | 基本持平 |
| 嵌套循环1e6 | 18,172 µs | 18,165 ~ 19,456 µs | 18,091 µs | 基本持平 |

**已排除的原因**：

- **优化等级**：两版源码默认都是 `-Og`（当前 `玄铁.xt:127`、8/16 版同处），且当前链顶显式加 `-O2` 后数字几乎不变（乘模 125,308 µs、分支 1,311,947 µs）→ 不是优化等级问题。
- **机器 / 语料 / 口径**：8/16 编译器在同一台机器、同一份语料上复现了历史数值（19,320 → 17.7~18.4 ms、252,965 → 232~245 ms），说明环境可比。
- **运行时**：两版编译器都从**同一份当前 `runtime/xt_runtime.c`** 链接（dev 布局下都回落到仓库源码），所以不是运行时差异。
- **正确性**：门禁与 127 用例全量回归全绿 → 是纯性能问题，不是功能缺陷。

**根因（已定位）**：提交 `3258029`（2026-08-17，"除模全走运行时"）把 `/` 与 `%` 从**静态整型快路径**和 **P-perf 接管块**里一起删掉，改为一律走运行时；而慢路径上还叠着运算符重载的字符串构造、字典查找与多次引用计数，于是每轮多出一次堆分配与一次字典查找。当年这么改的理由是**对的**——`select` 守卫挡不住 `sdiv` 的除零 UB（两侧都会求值，指令照样以 0 为除数执行）——但代价从未被测量（当时还没有 benchmark 门禁）。

**修法**：改用**控制流**守卫。P-perf 快路径先判除数是否为零，为零则跳运行时调用、非零才执行原生 `sdiv`/`srem`。除数为零时该指令**不被执行**，UB 无从发生；慢路径完整保留，故"除零返 0 / 有活跃尝试块则抛可捕捉异常 / 浮点混合提升"三套既有约定不变。字面量除数为 0 时 LLVM 会把 `icmp` 折叠为真，只剩运行时调用，同样满足"灭 undef"。

IR 对照（同一段取模循环）：

```llvm
; 修复前：字符串构造 + 字典查找 + 引用计数 + 运行时调用
%t23 = call %XTString* @xt_string_new(i8* %t22)
%t28 = call i64 @xt_dict_get(i64 %t21, i64 %t24)
%t45 = call i64 @"xt_mod"(i64 %t21, i64 %t44)

; 修复后：控制流守卫 + 原生指令
%t30 = icmp eq i64 %t29, 0
br i1 %t30, label %op.arithzero.11, label %op.arithcalc.10
op.arithcalc.10:  %t31 = srem i64 %t28, %t29
op.arithzero.11:  %t34 = call i64 @"xt_mod"(i64 %t21, i64 %t23)
```

**验证**：

- 本目录快照对比：乘模 −83.0%、分支 −77.1%（见上表）。
- 全量回归 **0 / 128**，其中 `Test/105_尝试捕捉` 保持通过——除零在有尝试块时可捕捉、无尝试块返 0，语义未变。
- 新增 `Test/136_除模语义与快慢路径.xt`：字面量零除、变量零除、尝试块内捕获、负数 C 语义、浮点混合提升、`商×除数+余数 == 原值` 不变式、循环取模校验和（钉"快而错"）。
- 自举门禁：定点 s3==s4 逐字节一致——链顶指纹随本次改动变化：`ad39771dd8d21991e30fadba8050f886`（3,146,097 字节）→ `e2c78af366395c517d67c163a15b79ed`（3,150,705 字节）。
- 差分对照：同一语义探针在 8/16 的旧编译器上**直接堆损坏崩溃**，当前编译器全部正确——该崩溃是 Aug-16 之后其他修复的成果，不计入本次修复。

**注意（快照口径）**：本次快照采集于凌晨，机器状态与上一次不同——**启动耗时（空程序，与本次改动无关）同期上涨 30.7%**，故上表中拼接/字典/浮点/嵌套的 +6%~+19% 判为环境漂移、不是代码回归。需要更干净的对照时，另择时间重跑两份快照即可。
