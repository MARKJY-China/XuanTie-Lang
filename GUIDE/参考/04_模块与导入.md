# 模块与导入

> 对标版本：XTC v1.0-rc.6-dev.9。

本章规定玄铁源文件之间如何组合成一个程序：引入语句 `引` 的语法与路径解析、别名的命名空间语义、模块级符号的可见性，以及项目根与铁铺包在编译期的作用边界。

玄铁的模块是**编译期**概念。`引` 把另一个源文件的顶层符号并入当前编译单元，最终产物仍是一个可执行文件；语言没有运行时动态加载，也没有 `.xti` 一类的独立接口文件。

## 编译单元与合并模型

一次编译由**一个主文件**加它（递归）引入的全部文件组成。处理分三个阶段：

| 阶段 | 行为 |
|------|------|
| 预扫描 | 递归读取每个引入目标，把其顶层函数、型、接口、全局变量登记进符号表；目标文件的词法/语法错误在此阶段直接报错退出 |
| 语义分析 | 递归处理引入、按父类拓扑排序解析型成员 |
| 代码生成 | 编译各模块体；全部模块合并进同一个 LLVM 模块 |

由此产生三条规范性结论：

1. **不存在“模块对象”。** 模块不能赋给变量、不能作为参数传递、不能按名动态查找。
2. **模块不是隔离的。** 引入后的符号在同一个命名空间里解析（有无前缀见「别名与命名空间」），模块内部看不到“引入方给它起了什么别名”。
3. **同一物理文件在一次编译中只预扫描、只编译一次**（按规范化后的绝对路径去重）。因此菱形引入（甲引丙、乙引丙）是安全的。

### 独立编译单元

> 在 v1.0-rc.6-dev.5 版本加入：`-lib`/`--库` 库编译模式，只产出 `.o` 对象、不生成 `@main`、不链接可执行文件。

```text
xtc tie 库甲.xt -lib -sc 库甲.o
```

库单元只导出其顶层符号。库单元若含顶层 `设`/`常` 初始化语句，`-lib` 下没有入口执行它们，编译器会明确警告；需要初始化的库应当导出显式的 `初始化()` 函数，由主程序调用。`-lib` 与 `pao`/`跑` 互斥。

完整用法见 [模块系统](../05_模块系统.md)。

## 引入语句

```text
引入语句    = "引" 路径字符串 [ "予" 别名 ] ;
路径字符串  = 字符串字面量 ;
别名        = 标识符 ;
```

规则：

- `引` 后必须是一个**字符串字面量**，其内容按字面使用，**不做字符串插值、不做表达式求值**（`引 "./#{名}.xt"` 不会展开）。
- 别名可省略；写 `予` 时其后必须是一个标识符（关键字不能作别名）。
- `引` 属于表达式前缀（对应 AST 节点「引入」），出现在语句位置时构成一条表达式语句。它的值没有意义，不能参与运算。
- `引` 应当写在**文件顶层**。当前实现只在顶层预扫描中处理引入；把 `引` 写进函数体不会按该源文件所在目录解析路径，实测报 `编译错误: 无法引入模块文件`。见「当前实现限制」。

语法示例：

```xuantie
引 "./库/数学.xt" 予 数学          // 带别名
引 "./库/文本.xt"                  // 不带别名：符号并入全局裸名空间
引 "渲染" 予 R                     // 铁铺裸包名
引 "I:\\项目\\共享.xt"             // 绝对路径（反斜杠需转义）
```

## 路径解析

路径解析只依据**引入方源文件所在目录**，与进程当前工作目录无关（裸包名的候选中会用到工作目录，见下）。

### 三类路径

| 形态 | 判定 | 解析方式 |
|------|------|----------|
| 绝对路径 | 首字符为 `/` 或 `\`，或第二个字符为 `:`（盘符） | 原样使用 |
| 相对路径 | 其余含分隔符、含 `.`、或以 `.` 开头者 | 拼接引入方文件所在目录 |
| 裸包名 | 不含 `/`、`\`、`:`、`.` 且不以 `.` 开头 | 按「搜索顺序」当作铁铺包名查找 |

### 规范化

解析结果必须规范化为**绝对路径**后才用于识别模块身份：

1. 分隔符统一为平台分隔符（Windows 为 `\`）；
2. 非绝对路径补上当前工作目录前缀；
3. 折叠 `.` 段与 `..` 段。

规范化的目的是让**同一物理文件的字符串身份唯一**。否则同一个文件经 `../temp/./_m.xt` 与 `../temp/_m.xt` 两种写法引入会得到两个身份，去重全部失效、模块被重复编译。

### 字符串字面量里的分隔符

源文件中的 `\` 是转义引导符，路径里的 Windows 分隔符必须写成 `\\`：

```xuantie
引 ".\m.xt"      // 词法错误：'\m' 是未知转义序列
引 ".\\m.xt"     // 合法，但触发 W006 警告
引 "./m.xt"      // 推荐写法
```

规范要求：**相对路径用 `/`，绝对路径用 `\`**。违反时编译器发 `W006`（路径规范）警告，不中断编译：

```text
路径不规范 [W006]：相对路径应使用 /，而非 \\ -> .\m.xt
```

`W006` 直接追加到警告列表：它**不受** `忽略警告` 配置抑制，也**不随** 严格度提升为错误（实测 `忽略警告 = ["W006"]` 且 `严格度 = "禁止"` 时仍只输出警告）。

### 搜索顺序（裸包名）

裸包名按下列顺序解析，命中即止：

| 顺序 | 候选位置 |
|------|----------|
| 1 | 工作目录下的 `lib\<包名>\<包名>.xt` |
| 2 | 工作目录上一级下的 `..\lib\<包名>\<包名>.xt` |
| 3 | 铁铺安装目录：`%TIEPM_HOME%\已安装\<包名>\<包名>.xt`（未设 `TIEPM_HOME` 时用 `%USERPROFILE%\.tiepm\已安装\`，POSIX 用 `$HOME`） |
| 4 | 同一目录下 `<包名>\<子目录名>\<包名>.xt`（GitHub 归档包会多包一层 `<包名>-<版本>\`） |
| 5 | 编译器自带库：编译器所在目录的 `lib\<包名>\<包名>.xt`，其次上一级的 `..\lib\<包名>\<包名>.xt` |

第 1、2 项排在最前是刻意的：在仓库根编译时若先命中铁铺安装副本，会出现「旧版库 + 仓库新版源码」的混搭产物，症状随安装时间漂移、极难排查。

当候选 3 与候选 5 同时存在且都能读出 `tiepm.toml` 的 `版本` 时：

- 版本不同 → **取版本较高者**；
- 版本相同 → 取安装副本；
- 任一边读不出版本 → 取安装副本（不猜测）。

两者版本不一致时编译器会打印提示，避免“用到了旧版库”被误认为“成员不存在”。

### 自引用与重复引入

| 情形 | 行为 |
|------|------|
| 引入路径规范化后等于引入方自身 | 报错退出：`编译错误: 检测到自引用 -> 文件 '…' 试图引用自身，这没有意义。请移除该引用语句。` |
| 同一文件以**相同别名**重复引入 | 允许，第二次直接跳过（幂等） |
| 同一文件以**不同别名**重复引入 | 报错退出：`编译错误: 模块 '…' 已以别名 '…' 引入，不允许再以别名 '…' 重复引入` |
| 引入后未使用任何符号 | 不报错、不告警（`W102` 已登记但当前实现从不发出） |

不同别名被拒绝的原因是模块内的裸名互调只能映射到一个命名空间。

### 循环导入

`甲引乙、乙引甲` **不会**被报错。由于每个文件在预扫描前就已登记为“已处理”，递归在第一层收敛，程序可正常编译运行：

```xuantie
// cyc_a.xt
引 "./cyc_b.xt"
函 a() { 返 1 }
```

```xuantie
// cyc_b.xt
引 "./cyc_a.xt"
函 b() { 返 2 }
```

```xuantie
// 主.xt
引 "./cyc_a.xt"
示(a())    // 1
示(b())    // 2
```

规范上不推荐循环导入：它使符号可见性依赖处理顺序，而顺序是实现细节。当前实现不提供“循环导入”诊断，见「当前实现限制」。

## 别名与命名空间

```text
模块符号名 = 别名 "." 名称      // 有别名
模块符号名 = 名称              // 无别名
```

### 有别名

`予 别名` 后，被引入文件的顶层函数、型、接口、全局变量全部以 `别名.名称` 的形式登记：

```xuantie
引 "./库/文本.xt" 予 文本
示(文本.拼接("甲", "乙"))
```

- 前缀是**扁平**的，不与外层模块前缀复合。`UI.xt` 内写 `引 "渲染.xt" 予 R`，其符号登记为 `R.开窗口`，而不是 `UI.R.开窗口`——否则模块体内的 `R.开窗口` 调用永远匹配不上。
- **模块内部的互调使用裸名。** 模块自己并不知道引入方给了它什么别名；编译器在解析裸名时会回退到当前模块命名空间：

  ```xuantie
  // ui.xt
  公 函 四边(值) { 返 值 * 4 }
  公 函 全边(值) { 返 四边(值) }     // 裸名互调，等价于 UI.四边(值)
  ```

  但引入方**不能**用裸名调用 `四边`（`示(四边(3))` 报 `未知标识符 '四边'`），必须写 `UI.四边(3)`。
- 模块内对自身全局变量的前向引用同样成立：模块函数体可以先于该 `设`/`常` 语句引用它。
- 别名可被同名局部变量遮蔽：局部符号优先于模块别名（回归用例 `Test/165_模块别名可被局部变量遮蔽.xt`）。

### 无别名

省略 `予` 时，被引入文件的顶层符号以**裸名**登记进同一符号表（“全局合并模式”），没有前缀：

```xuantie
// m.xt
设 模块级变量 = 7
函 裸函数() { 返 41 }
```

```xuantie
// 主.xt
引 "./m.xt"
示(裸函数())        // 41
示(模块级变量)      // 7
示(m.裸函数())      // 错误：未知标识符 'm'
```

注意：**不存在“以文件名作默认前缀”的规则**。部分既有文档（[模块系统](../05_模块系统.md)、[引](../关键字/引.md)、[予](../关键字/予.md)）写有“不带 `予` 时以文件名作访问前缀”，与当前实现不符；实测无前缀，且 `m.裸函数()` 报 `未知标识符 'm'`。以本章为准。

无别名合并的代价是**顶层名字必须全局唯一**。两个文件都有 `函 撞名()` 时，前端不会报“重复定义”，冲突会漏到链接前的 clang：`error: invalid redefinition of function '撞名'`。需要隔离时一律用 `予`。

## 模块级符号

被引入文件的下列顶层声明构成模块符号：

| 声明 | 作为符号登记 | 可被 `别名.名` 访问 |
|------|--------------|--------------------|
| `函 名(...)` | 函数名 | 是 |
| `型 名 { ... }` | 型名（其方法另行登记为 `名.方法名`） | 是 |
| `口 名 { ... }` | 接口名 | 是 |
| `设 名 = ...` / `常 名 = ...` | 全局变量名 | 是 |
| `外 函 名(...)` | 外部函数名（C ABI） | 是 |

规范：

- 模块符号只由**顶层**声明产生。函数体内部的 `设` 不是模块符号。
- 顶层 `设`/`常` 是**全局变量**（静态存储），在任意模块的函数体内可见；顶层块内的 `设`（如顶层 `若` 分支里）同样注册为全局符号。
- **被引入模块的顶层语句会执行**：模块顶层语句在编译时并入同一入口，运行时先于主文件顶层语句执行（实测模块顶层 `示(...)` 先于主文件输出）。`-lib` 库模式不生成入口，此时顶层语句不执行。
- 模块符号的初始化语句按模块被编译的顺序执行，不保证跨模块的初始化先后。

## 可见性：公、私、护

```text
可见性 = "公" | "私" | "护" ;
```

可见性可写在 `型` 的成员声明前，也可写在顶层声明前（`设`、`常`、`弱 设`、`函`、`型`）。成员产生式见 [复合语句](./07_复合语句.md#型口)。

| 修饰符 | 含义 | 强制检查点 |
|--------|------|------------|
| `公` | 公开，缺省级别 | 无限制 |
| `私` | 仅定义它的型内部可访问 | 实例成员访问、成员赋值、成员方法调用 |
| `护` | 定义它的型及其子类可访问 | 同上；全局范围访问直接报错 |

规范：

- 可见性检查只对**型成员**生效。判定依据是接收者的静态类型——只有当接收者类型带 `型:` 前缀（即实例）时才查可见性表。
- **模块顶层符号的 `公`/`私`/`护` 不构成访问门禁。** 顶层 `私 函` 仍可被 `别名.名` 或裸名调用，编译器对此不发诊断。顶层的 `公` 是显式标注，不是控制手段。这与 [公](../关键字/公.md) 的说明一致。
- `私` 严格限定在定义型内部：子类也不能访问父类的 `私` 成员。
- `护` 在继承链内放行：`是子类?(当前型, 定义类)` 为真即可；当前型为空（全局范围）一律报错。
- `型` 体内不写修饰符即 `公`。

诊断原文：

```text
[示例.xt 行:3, 列:4] 成员 'a' 是私有的，只能在型 'T' 内部访问
[示例.xt 行:3, 列:4] 成员 'a' 是受保护的，不能在全局范围访问
[示例.xt 行:3, 列:4] 成员 'a' 是受保护的，只能在型 'A' 及其子类中访问
```

## 项目与 `玄铁.配置.toml`

含 `玄铁.配置.toml` 的目录即**项目根**。编译器与 LSP 都从当前文件所在目录**向上逐级**查找该文件来定位项目根；找不到就按“无配置”处理，不报错。

配置是极简的行式解析：`[节]` 行切换当前节，`键 = 值` 行登记键值；值两侧的引号与空白被剥掉，`[ ... ]` 形式的值按逗号切分成列表。键同时以裸键和 `节.键` 两种形式登记。

| 配置项 | 作用 |
|--------|------|
| `[项目] 入口 = "主.xt"` | 裸跑 `xtc 铁`（不带源文件）时的编译目标，相对项目根解析 |
| `[编译] 严格度 = 默认/严格/禁止` | 警告级别策略；命令行 `--严格`/`--禁止` 优先于配置 |
| `[编译] 忽略警告 = ["W001","隐式类型"]` | 按警告码或类别名静默跳过对应警告 |
| `[原生] 源 = ["桥.c", "子目录/其他.c"]` | 项目级 C 源，链接前用 clang 现场编译；相对路径按项目根解析 |

规范性要求：

- 未指定源文件且项目根未声明 `[项目] 入口` 时，编译器**明确报错并给出用法**，不猜测编译目标。
- `[原生] 源` 声明的文件缺失或编译失败一律报错退出，不静默跳过。
- `玄铁.配置.toml` 只影响编译与链接参数，**不参与模块解析**：它不改变 `引` 的搜索顺序，也不提供“模块别名映射”。

## 铁铺包与 `[原生]` 对象

铁铺（TiePM）负责包的下载、校验、安装与依赖解析；编译器只负责把**已安装**的包接入编译。本节只描述这条边界。

- 包入口文件名必须与包名一致：`<安装目录>\<包名>\<包名>.xt`（或 GitHub 归档布局下多一层子目录）。找不到时编译器报：

  ```text
  编译错误: 无法解析铁铺包引用 '不存在的包'
    来源文件: …\主.xt
    提示: 请先执行 '铁铺 安装 不存在的包' 安装此包
    如果已安装，请检查 <安装目录>\不存在的包 目录
  ```

- 编译器**不读** `[依赖]`、不下载、不校验哈希、不做版本求解。这些全部属于铁铺。编译器与铁铺的唯一交点是“已安装目录里有没有那个入口文件”，以及下一条的原生对象登记。
- 编译器读取的 `tiepm.toml` 字段只有两个：`版本`（用于安装副本与自带副本的优先级比较）与 `[原生] 对象`。

### `[原生]` 对象

被引入模块**所在目录**的 `tiepm.toml` 若声明了 `[原生]` 段，其中的对象文件会在引入时登记，链接期并入：

```toml
[原生]
对象 = ["sqlite3.o", "SQLite桥.o"]
```

规则：

- 条目按**模块目录**拼接成绝对路径（不是项目根、不是工作目录）。
- 缺失即明确报错退出：

  ```text
  错误: 模块声明的原生对象不存在: …\sqlite3.o
    该模块目录的 tiepm.toml [原生] 对象列表引用了缺失文件,请重新安装该包
  ```

- 对象文件会先复制到缓存目录（按内容指纹命名，非 ASCII 路径经此中转）再交给链接器。
- 解析是刻意极简的：只认 `[原生]` 段内 `对象` 行上的双引号串，不是通用 TOML 解析器。字段名之外的内容、跨行数组都不保证被识别。
- 与项目级 `[原生] 源` 的区别：`对象` 是**已编译好的 `.o`**，随包分发；`源` 是**项目自带 `.c`**，每次按内容指纹重编。两者都只解决“把原生代码接进链接”，不解决包管理。
- 路径写错、对象架构与目标不匹配等属链接期错误，由链接器报告。

## 错误与诊断

| 场景 | 诊断 |
|------|------|
| `引` 后不是字符串 | `期望引入路径字符串` |
| `予` 后不是标识符 | `期望别名标识符` |
| 相对路径文件不存在 | `编译错误: 无法预扫描模块文件` + 来源文件 / 引入路径 / 解析为（文件不存在） |
| 裸包名无法解析 | `编译错误: 无法解析铁铺包引用 '…'` |
| 自引用 | `编译错误: 检测到自引用 -> …` |
| 同一文件多个别名 | `编译错误: 模块 '…' 已以别名 '…' 引入，不允许再以别名 '…' 重复引入` |
| 引入文件词法错误 | `引入文件词法错误 —— <路径>`，逐条打印后退出 |
| 引入文件语法错误 | `引入文件解析错误 —— <路径>`，逐条打印后退出 |
| 模块中无此成员 | `[文件 行:x, 列:y] 模块 '别' 中未找到成员 '名'` |
| 相对路径用了 `\` | 警告 `W006`（斜杠混用） |
| 引入后完全未使用 | 无诊断（`W102` 未使用导入已登记但当前不产生） |

导入失败的诊断一律**带来源文件与解析后的绝对路径**——这是定位“路径看起来对但文件不在那儿”的唯一有效信息。

## 当前实现限制

以下均为**未支持**或**与文档承诺不符**的行为，不要依赖：

- **循环导入没有诊断。** 官方文档称“循环引用会被检测并报错”，当前实现不报错，`甲↔乙` 可正常编译运行（见「循环导入」）。
- **无文件名默认前缀。** 省略 `予` 时符号以裸名并入全局，不存在 `文件名.成员` 的访问方式。
- **顶层可见性不生效。** 模块顶层的 `私`/`护` 不被强制检查，所有顶层符号对引入方可见。
- **顶层重名不诊断。** 无别名合并时两个模块的同名顶层符号不会在前端报重复定义，冲突漏到 clang（`invalid redefinition`）。
- **`引` 只能在顶层。** 写进函数体时路径不会按源文件目录解析，实测报 `编译错误: 无法引入模块文件`。
- **`玄铁.配置.toml` 不参与模块解析。** 它不改变搜索顺序，也不提供别名映射；配置解析只覆盖 `键 = 值` 与 `[...]` 数组。
- **编译器不解析 `[依赖]`。** 依赖求解、下载、哈希校验由铁铺负责，编译器只看安装目录里是否存在入口文件。
- **`[原生]` 解析不是通用 TOML。** 仅识别 `[原生]` 段的 `对象` 行；跨行数组、注释内引号等不保证正确。
- **未使用导入无诊断。** 警告码 `W102`（未使用导入）已登记，但当前实现从不发出；`W101`（未使用变量）亦未见实际输出。
- **`W006` 不受抑制配置影响。** 它绕过统一的警告等级机制，`忽略警告` 与严格度都改不了它。
