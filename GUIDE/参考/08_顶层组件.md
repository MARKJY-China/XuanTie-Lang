# 顶层组件

> 对标版本：XTC v1.0-rc.6-dev.5。

本章规定编译单元（`.xt` 源文件）顶层可以出现什么、各组件在运行期的职责，以及入口与初始化由谁承担。记法见 [概述与记法](./00_概述.md)；“当前实现”指本仓库的 XTC 自举编译器与 `runtime/xt_runtime.c`。

## 规范性规则

### 程序组成

一个编译单元由下列顶层组件构成，可出现任意多次、按任意顺序书写（`引` 除外，见下）：

| 组件 | 语法形态 | 运行期产物 |
|------|----------|------------|
| 导入 | `引 "路径" [予 别名]` | 无（把被引单元的顶层组件并入本单元） |
| 外部函数声明 | `外 函 名(参数): 返回类型` | LLVM `declare`（无函数体） |
| 函数定义 | `[公\|私\|护] 函 名(参数) [: 类型] { … }` | 独立函数 |
| 型定义 | `[公\|私\|护] 型 名 [<T>] [承 父] { … }` | 无独立运行期布局；方法各成一个函数，符号名为 `型名.方法名` |
| 接口定义 | `口 名 [<T>] { 函 签名… }` | 无运行期产物，仅作编译期约束 |
| 全局变量 | `[公\|私\|护] 设 名 [: 类型] = 表达式` | 全局槽位 + 一条初始化语句 |
| 全局常量 | `[公\|私\|护] 常 名 [: 类型] = 表达式` | 全局槽位 + 一条初始化语句（禁再赋值） |
| 顶层语句 | 任意语句 | 直接进入入口桩主体 |

- `引` 必须位于其引入符号被使用之前（语义上等价于在该位置并入被引单元的顶层组件）。
- 顶层语句可以与声明交错书写；执行顺序就是书写顺序。

### 全局 `设` / `常`

- 顶层 `设` 与 `常` 都发射为**进程级全局槽位**，静态初值为 `0`（即 `空`），在对应初始化语句执行时写入第一个值。
- `常` 只禁止赋值：任何对 `常` 名的赋值都是编译期错误（“常量 'X' 不能重新赋值”）；它没有额外的不可变性保护，也不产生只读内存。
- 全局槽位在函数体内同名 `设` 时被**遮蔽**：函数内的 `设 x` 新建局部槽位，不写全局；写全局的正当形式是裸赋值 `x = …`。
- 全局变量不进入闭包/异步的值快照：函数、闭包与异步块都按符号直接读写同一槽位，因此全局是跨任务共享数据的合法通道。

### 外 函

- `外 函` 只声明签名、不产生实现；符号必须真实存在于所链接的 C 库或 runtime 中，否则链接阶段失败。
- 同名声明只发射一次（预扫描去重）。
- 参数与返回类型必须逐一标注；注解决定 ABI（见“运行时语义”中的 ABI 表）。签名与 C 侧不符时不会在编译期被发现，只在链接或运行期暴露。
- **返回值必须符合玄铁值编码**：带对象头的堆对象指针、标记整数、或 `真`/`假`/`空` 小常量。返回裸 C 指针（无对象头、LSB = 0 且地址 > 4096）会在首次 `retain`/`release` 时触发“堆损坏或非法指针访问”并硬退出。
- `整` 返回值还必须在 ±(2⁶²−1) 域内；C 侧必须用 `XT_FROM_INT(值)` 编码，不能直接返回裸 `int64_t`。
- runtime 内建也是通过这条通道暴露的，例如取命令行参数需自行声明：`外 函 xt_get_args(): 数组`。

### 模块级 `函` / `型` / `口`

- 顶层 `函` 定义发射为独立函数，可被同单元任意位置（包括定义之前的语句）调用——符号由预扫描先行登记。
- `型` 是编译期构造：字段声明与方法定义被登记到类型表，方法被改写为以 `此` 为第一个形参的普通函数；实例本身是字典兼容的堆对象。`型` 不发射任何独立的数据段或虚表。
- `口` 只登记方法签名，不生成代码，也不检查“某型是否实现某口”——当前没有显式实现声明语法。
- 成员与方法可见性（`公`/`私`/`护`）在编译期按接收者的静态类型检查。
- `型` 体内只解析成员声明（`设`/`函`/`弱 设`/`覆 函`）；误写进型体的普通语句被跳过，不执行也不报错。

### 入口：顶层执行的位置

- 可执行程序没有用户可见的“主函数”。编译器发射固定的入口桩，主体就是**顶层语句序列**（详见 [执行模型](./03_执行模型.md)）：

```text
@main(argc, argv):
    xt_init()
    xt_init_args(argc, argv)
    <顶层语句序列>
    xt_scheduler_run()
    ret 0
```

- `主` 不是关键字，也不存在“名为 `主` 的函数会被调用”的约定。
- 顶层 `返 值` 直接成为入口桩的返回值，即进程退出码（截断为 32 位）；顶层 `终 值` 是显式 `exit`。二者之外的正常结束退出码为 `0`。

### 项目模式

- 未在命令行给出源文件时，编译器从当前工作目录向上逐级查找 `玄铁.配置.toml`；找到即视为项目根，读取 `[项目] 入口` 作为编译目标：

```toml
[项目]
入口 = "主.xt"
```

- 入口路径按项目根（配置文件所在目录）解析。找不到配置、或配置未声明入口时，编译器明确报错并退出（不猜测目标文件）。
- 同一配置文件还承载编译严格度与项目级原生 C 源等设置（见 [类型系统哲学设计](../02_类型系统哲学设计.md)）。

### 编译单元与库模式

- 默认模式：`引` 把被引单元**并入**当前单元，全部模块合并为一个 LLVM 模块，输出单一可执行文件；同一物理文件按规范化绝对路径去重（菱形引入安全），同一模块在一次编译中只能使用一个别名。
- 库模式（`-lib` / `--库`）：只产出对象文件，不发射入口桩、不链接可执行文件。库单元只导出其顶层符号，因此多个库对象可以与主程序同时链接而不冲突。
- 库单元若含顶层 `设`/`常` 初始化语句，库模式**没有入口执行它们**：编译器明确告警，并提示改为导出显式 `初始化()` 函数由主程序调用。该告警不是错误，产物仍会生成。
- 玄铁侧没有“选择导出”：库对象包含其全部顶层符号；跨单元访问用 `别名.名`（省略 `予` 时按裸名并入同一符号表），只有 C ABI 导出名可定制。
- C ABI 另有显式导出形态 `公 函 名(…): 类型 为 "导出名" { … }`，它只决定 C 调用方看到的符号名与包装，不改变玄铁侧可见性（见 [C ABI互操作](<../C ABI互操作.md>)）。
- 顶层的 `公`/`私`/`护` 只被接受为声明修饰，**不产生访问检查**：可见性检查当前只覆盖型成员。需要封装请把成员放进 `型`。

### 初始化职责划分

| 阶段 | 承担者 | 内容 |
|------|--------|------|
| 运行时初始化 | 入口桩调用 `xt_init()` | 控制台 UTF-8、弱引用锁、记录主线程、线程池（worker = CPU 核数，上限 64）、网络子系统、用户态调度器 |
| 参数初始化 | 入口桩调用 `xt_init_args()` | `argc`/`argv` 转为字符串数组；第 0 项为程序自身路径；供 `xt_get_args()` 读取 |
| 单元初始化 | 顶层语句 | 全局槽位赋值、注册、启动任务等一切用户初始化 |
| 收尾 | 入口桩调用 `xt_scheduler_run()` | 驱动 fiber、有界排空线程池，然后返回 |

- 语言层没有独立的初始化函数、没有 `.init` 段、没有按单元的构造顺序表：单元初始化就是顶层语句。

## 运行时语义

### 全局槽位

- 每个顶层 `设`/`常` 对应一个 `global i64` 槽位，初始值为 `0`。
- 进入 `@main` 前所有全局槽位均为 `0`；声明语句执行后才有值。因此在初始化语句之前调用引用该全局的函数，读到的是 `空`（实测）。
- 全局槽位的覆盖写（重复 `设` 或裸赋值）会先释放槽位旧值，再存入新值；首轮旧值为 `0`，释放是空操作。

### 符号解析与前向引用

- 预扫描阶段登记全部顶层符号（函数、型、全局），因此函数体、型方法、闭包都可以引用**文本上后出现**的顶层符号。
- 函数内同名 `设` 遮蔽全局（新建局部），弹层时恢复全局可见性；裸赋值则写穿到全局槽位。
- 顶层语句之间没有前向保证：语句按书写顺序执行，后续声明在被执行前不存在有效值。

### 外 函 调用 ABI

参数按注解决定传递形态，只有 `原生小数` 脱壳为原生 `double`，其余一律按玄铁值原样传递：

| 注解 | 形参传递 | 返回值接收 |
|------|----------|------------|
| 未标注 / `整` | 装箱 `i64`（标记整数：`(值<<1)\|1`） | `i64`（必须是标记整数或对象指针） |
| `字` | 玄铁字符串**对象指针**（`XTString*`），不是 C `char*` | `i8*`；必须指向真正的玄铁字符串对象 |
| `布尔` | 哨兵 `i64`（`真=4`、`假=2`） | `i64`；读侧判 `4` 或 `1` 为真，打包回 `4`/`2` |
| `小数` | 装箱 `XTFloat` 对象指针 | `i64`（装箱对象指针） |
| `原生小数` | 原生 `double` | `double`（原生 ABI，用于 libm/标准 C 库） |
| `空` | — | `void` |

- 该表意味着：**不存在“整 自动脱壳”通道**。直接声明一个参数为 `整` 的 C 函数（如 `abs`）会收到带标记位的整数，结果无意义。与 C 交互必须写按玄铁值编码的桥函数，或用 `原生小数` 走原生 ABI。
- `布尔` 的双约定只放宽返回值读取：C 侧返回 `0/1` 或返回玄铁哨兵 `4/2` 都可，返回其它非零值（如 `5`）会被判为假。

### 单元合并

- 被引单元的顶层语句在 `引` 出现处并入并执行（实测：模块的初始化输出出现在 `引` 的位置），因此初始化顺序是“展开后的文本顺序”。
- 同一物理文件只并入一次；别名不一致是编译错误（同一模块在一次编译中只能有一个命名空间）。
- 合并后所有单元共享一个平坦的符号空间与一个全局区；循环引用被检测并报错。

## 错误与诊断

| 场景 | 诊断 | 性质 |
|------|------|------|
| 对 `常` 赋值 | 编译错误：常量 'X' 不能重新赋值 | 编译期中断 |
| 同一模块使用两个别名 | 编译错误 | 编译期中断 |
| 循环 `引` | 编译错误 | 编译期中断 |
| 引用未声明的顶层符号 | 编译错误：未知标识符（附相近关键字提示） | 编译期中断 |
| 项目模式找不到配置或未声明入口 | 错误：未指定源文件；且未找到声明 `[项目] 入口` 的配置；并给出两种修法 | 编译期中断 |
| 库模式含顶层初始化语句 | 警告：不生成 main 入口，顶层初始化语句不会被执行 | 警告，产物仍生成 |
| `外 函` 声明的符号在链接时不存在 | 链接失败，保留中间产物并打印可手工重试的链接命令 | 链接期失败 |
| `外 函` 返回值违反值编码（裸 C 指针） | 运行期“堆损坏或非法指针访问”，退出码 `255` | 硬退出 |
| `外 函` 返回越域整数 | 该值在首次解码/打印时显式诊断（标记整数解码越域）并退出 | 硬退出 |
| 型体内写普通语句 | 不诊断、不执行（被跳过） | 静默忽略 |
| 顶层 `返` 返回非整值 | 无诊断，按 32 位截断后的值作为退出码 | **未定义**语义，不得依赖 |

## 当前实现限制

- 没有用户入口函数（无 `主()`）、没有单元级初始化函数、没有 `.init` 段；需要被库使用者显式调用的初始化必须自己导出，例如 `初始化()`。
- `-lib` 下顶层初始化语句不会执行，只有警告没有替代机制。
- `外 函` 的 ABI 是“除 `原生小数` 外全部装箱传值”，因此不能直接声明标准 C 函数签名（`int`/`char*`）来调用；桥函数是唯一正路。
- 玄铁侧没有“选择导出”：库对象包含其全部顶层符号，只有 C ABI 导出名可定制。
- `口` 无实现检查、无运行期产物，也不参与方法解析。
- 顶层 `返` 复用函数返回路径，按入口的 `i32` 约定截断；这是实现细节而非语言特性。
- 顶层语句没有“初始化完成”标记：早于初始化语句的跨函数访问只能读到 `空`（未定义行为，实际是空槽位）。
- 未定义：多个单元中同名顶层符号的解析优先级（合并是平坦的，重名行为不被规范保证）。
