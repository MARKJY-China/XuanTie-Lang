# 执行模型

> 对标版本：XTC v1.0-rc.6-dev.9。

本章规定玄铁程序从进程启动到退出的执行语义：程序结构与入口、顶层初始化、调用与返回、错误处理、异步与并发、调度与退出。记法见 [概述与记法](./00_概述.md)；“当前实现”指本仓库的 XTC 自举编译器与 `runtime/xt_runtime.c`。

## 规范性规则

### 程序结构与入口

- 一个可执行程序由一个**主单元**及其递归 `引` 入的模块组成。默认模式下这些单元合并为一个 LLVM 模块、产出单一可执行文件（见 [模块与导入](./04_模块与导入.md)）。
- 编译器为可执行程序发射不依赖用户代码的入口桩，固定顺序为四步：

| 顺序 | 动作 | 职责 |
|------|------|------|
| 1 | `xt_init()` | 运行时初始化：控制台 UTF-8、弱引用锁、记录主线程、启动线程池、网络子系统、用户态调度器 |
| 2 | `xt_init_args(argc, argv)` | 把命令行参数转成字符串数组，供 `外 函 xt_get_args(): 数组` 读取 |
| 3 | 顶层语句序列 | 全局初始化与主逻辑 |
| 4 | `xt_scheduler_run()` | 驱动用户态调度器并排空线程池，然后返回 `0` |

- **不存在 `主()` 入口约定**：`主` 不是关键字，`函 主()` 只是一个普通函数，不会被自动调用。程序的“main”就是顶层语句序列。
- `-lib`/`--库` 库编译模式不发射入口桩，只产出可链接对象（见 [顶层组件](./08_顶层组件.md)）。

### 顶层初始化

- 顶层语句按**合并后的文本顺序**执行：模块的顶层语句在其 `引` 出现的位置并入并执行（实测：被引模块的初始化输出出现在 `引` 的位置）。
- 顶层 `设`/`常` 是进程级全局槽位，静态初值为 `0`（即 `空`），在对应声明语句执行时被写入。
- 因此“函数可以在声明之前引用全局”（符号由预扫描登记），但“在初始化语句执行之前调用该函数”读到的是 `空`，不是最终值（实测）。
- 全局初始化没有独立阶段，也没有隐式初始化函数；顺序即书写顺序（含 `引` 的展开顺序）。

### 函数调用与返回

- 每次玄铁函数调用对应一次原生调用；参数以装箱机器字传递，被调函数在入口对装箱参数 `retain`，离开作用域时 `release`。
- 带标量注解（如 `整`）的形参在入口脱壳为裸整数存储；收到非标量实参是硬错误（有活动 `尝试` 时转为可捕）。
- `返 值` 把表达式的 `+1` 引用移交调用方；函数没有 `返` 时落到 `ret i64 0`，调用方得到 `空`。
- 函数是一等值：裸函数名作值时包装为函数对象，可通过变量动态调用。
- 递归深度不做检查；深度超出原生线程栈会导致进程崩溃（**未定义**）。

### 结果与 `尝试` / `捕捉`

- `结果` 是普通值：可预期失败编码为返回值，由调用方判 `.成功` 后取 `.值` 或 `.错误`。
- `?` 后缀是语法糖：成功取 `.值`，失败立即返回该 `结果` 给上一层；作用于非 `结果` 是硬错误（退出码 1）。
- `尝试`/`捕捉` 用于兜底“编程错误”类运行时故障，实现为**深度计数 + 挂起标志 + 语句级轮询**（不使用 `setjmp`）：

| 阶段 | 行为 |
|------|------|
| 进入 `尝试` | 深度 +1，清除上一次的错误位置 |
| 块内每条语句后 | 轮询挂起标志，命中即跳转到 `捕捉` |
| 进入 `捕捉` | 清除挂起标志，供读取异常消息 |
| 离开 `尝试`/`捕捉` | 深度 -1 |

- `尝试` 的粒度是**语句**：故障语句会执行完（可能已完成部分副作用）再进入 `捕捉`。
- 可捕范围与硬退出范围以 [关键字/尝试](../关键字/尝试.md) 为准；跨函数的成员/索引/方法硬错误不转异常。
- 异常处理状态（深度、挂起标志、消息）是**线程局部**的，`异步`/`并行` 块内可以使用 `尝试`；不同任务互不串扰，但不要跨任务共享同一个 `尝试` 结果变量。

### 异步块与 fiber 状态机

`异步 { … }` 创建并发任务并立即返回任务句柄。执行层由编译器按块内容静态选择，规则按优先级如下：

| 条件 | 执行层 | 说明 |
|------|--------|------|
| 挂起点出现在**循环体内**（`等待`、`.收`、`.发`、`选`、`时.睡`、`连`、`流.读`、`流.写`） | 线程池 | 无栈状态机无法跨 poll 保留循环局部状态；编译期打印提示 |
| 含 `求`/`执`/`输` | 线程池 | 三者是 C 侧全程阻塞实现，无 fiber 非阻塞路径；编译期打印提示 |
| 有**语句级**挂起点，且以上均不成立 | fiber 状态机 | 挂起让出调度器线程 |
| 无任何挂起点 | 线程池 | 整块编译为一个独立函数提交执行 |

fiber 状态机（当前实现）：

- 编译器为块生成一个状态结构体（状态号 + 每个挂起点的结果槽 + 捕获字段 + 块内局部字段）和一个 `poll` 函数；每次 `poll` 从当前状态推进到下一个挂起点。
- **捕获**：外层**局部变量**在启动时刻做值快照（逐项 `retain` 后存入状态字段）。因此启动后外层再改，块内看不到；块内改了也不写回外层（实测）。**全局变量**不进入快照，块内按符号直接读写同一槽位。
- 各挂起点的挂起方式：

| 挂起点 | 未就绪时的动作 | 唤醒条件 |
|--------|----------------|----------|
| `等待(任务)` | 先试一次，未完成则挂起在目标任务上 | 目标任务完成 |
| `道.收()` / `道.发(值)` | 先试一次（零超时），未就绪则挂起在该通道上 | 该通道有数据/有空位 |
| `选([通道…], 毫秒)` | 零超时试选，未就绪则睡眠 1ms 后重试，直至截止 | 截止或某通道就绪 |
| `时.睡(…)` | 注册到调度器定时器堆 | 到期 |
| `连`、`流.读`、`流.写` | 置为非阻塞并挂起在该 socket 上 | socket 可读/可写/可连 |

- 状态机在挂起时把当前状态号写入状态结构体，返回“未完成”；调度器在唤醒后从该状态继续，不重放已完成的前序语句。
- `返 值` 在状态机内表示“本任务完成”，把值写入结果槽并以完成态结束。

### `并行`

- `并行 { {…} {…} … }` 把每个分支编译为独立函数并立即提交线程池，随后**按书写顺序**逐个等待，返回结果数组；分支的 `返` 值成为对应元素，无 `返` 为 `空`。
- 结果顺序按分支书写顺序，不按完成先后。
- 分支**不是闭包**：分支函数只继承全局符号。分支内引用外层**局部变量**在当前实现下不报错，但求值为 `空`（实测）——不要依赖任何外层局部变量，需要数据请用全局、参数或通道。

### `等待`

- `等待(任务)` 消费任务句柄并返回其结果；没有 `返` 的任务得到 `空`。
- 结果只能消费一次：槽位回收后再次 `等待` 同一句柄得到 `空`。
- 在普通上下文（顶层、普通函数）中，`等待` 会驱动调度器取回结果；fiber 句柄走“驱动调度器 + 取槽位 + 回收槽位”，线程池任务走“线程池等待 + 移交结果”。
- 在 fiber 内部，`等待` 是挂起点：先试一次，未完成则挂起，不占用调度器线程。
- `等待` 驱动调度器时只推进就绪/定时/等待队列，不为无关线程池任务无限自旋（当前实现，见 [关键字/异步](../关键字/异步.md) 的退出预算说明）。

### 道与选

- `道(容量)` 创建带缓冲通道，缺省容量 `16`；满时发送阻塞、空时接收阻塞。
- `发`/`收` 的执行语义按上下文区分：

| 上下文 | `收()` | `收(毫秒)` | `发(值)` |
|--------|--------|------------|----------|
| 顶层 / 普通函数 | 无限阻塞；等待期间驱动调度器（重入保护） | 支持：`0` 非阻塞、`>0` 限时、`<0` 无限 | 阻塞直到有空位；等待期间同样驱动调度器 |
| `异步` 块（fiber） | 挂起点：试收一次，空则挂起 | **编译错误**（不支持带超时的挂起收） | 挂起点：试发一次，满则挂起 |
| `异步` 块（线程池） | 原语阻塞调用 | 原语阻塞调用 | 原语阻塞调用 |

- 容量为 `0` 的通道不被支持：`发` 直接丢弃，`收` 只能等到超时或被唤醒。当前实现没有无缓冲通道语义。
- `选([通道…], 超时毫秒)` 返回首个就绪通道的下标；`0` 为非阻塞探测，超时返回 `-1`，负超时为无限等待。它只报告“哪个就绪”，不取数据。
- 主线程等待期间 `选` 会驱动调度器，因此返回可能晚于给定超时（若 fiber 内有长睡眠正在被驱动）。

### 阻塞原语与线程池语义

| 原语 | 实现性质 | 是否参与异步路由判定 |
|------|----------|----------------------|
| `求(地址)` | C 侧全程阻塞（连接、重定向、读取） | 是（含之则整块线程池） |
| `执(命令[, 超时毫秒])` | 建管道、隐藏窗口、等子进程结束 | 是 |
| `输(提示)` | 阻塞读标准输入 | 是 |
| `进程.启动/写/刷新/关闭输入/等退出` | 同步阻塞的文件/管道 I/O | 否 |
| `文件.读`/`文件.写` | 同步阻塞 I/O | 否 |
| `听(端口, 回调)` | 自起接受线程，回调在新线程执行 | 否（不是挂起点） |

- 上表“参与判定”为否的阻塞调用若落在一个被判为 fiber 的异步块里（例如块内另有 `等待`），会直接占用调度器线程，使同进程其它 fiber 停摆。需要隔离时把这些调用放进含 `求`/`执`/`输` 的块，或放进无挂起点的块（后者本来就走线程池）。
- `执` 的超时参数 `>0` 时超时后终止整棵子进程树并返回失败 `结果`；`<=0` 表示不超时。

### 进程退出码

| 结束方式 | 退出码 |
|----------|--------|
| 顶层语句执行完，调度器排空后正常返回 | `0` |
| `终 值` | `值` 截断为 32 位 |
| 顶层 `返 值`（入口桩返回约定） | `值` 截断为 32 位；非整数结果无意义 |
| 运行时硬错误（成员/索引/方法/参数类型/`?` 误用/内存不足/池耗尽/定时器溢出） | `1` |
| 堆损坏或非法指针 | `255`（`exit(-1)`） |
| 子进程 | 以子进程自身退出码报告给调用方，不影响本进程退出码 |

## 运行时语义

### 调度器状态与生命周期

- fiber 状态集：`READY`、`WAITING`（等任务）、`SLEEPING`（等定时器）、`DONE`、`RUNNING`。
- 就绪队列是 FIFO；定时器是按下标唤醒时间组织的小顶堆（容量 `8192`，溢出即硬错误）。
- 主循环每轮：取当前时间 → 到期定时器入就绪队列 → 轮询 socket 就绪 → 出队一个就绪 fiber 执行一次 `poll`。
- 就绪队列为空且存在 `WAITING` 时，等待 1ms 后把全部 `WAITING` fiber 重新入队重试——这是“丢失唤醒”的兜底，重试幂等：未就绪者会再次挂起。
- 同一时刻只允许一个线程驱动调度器；后到者直接返回，由先到者继续驱动。
- 主线程若长期停留在自有循环里（UI 帧循环等），就不会再回到入口桩的 `xt_scheduler_run()`，fiber 将整体不被驱动；运行时为此提供非阻塞单步泵 `xt_scheduler_step`（跑一拍即返回），由库在帧循环中显式调用。
- fiber 池上限 `65535`，句柄为槽位下标 + 1；槽位在“已完成且结果已被消费”后回收入空闲栈复用。池耗尽时显式报错退出，不返回非法句柄。

### 线程池

- worker 数量为 CPU 核数，上限 `64`；任务函数签名统一为一元函数，返回结果值。
- 每个任务在 worker 上执行完毕后写入任务结果、置完成态，并唤醒等待该任务的对象。
- `并行` 分支与线程池异步块都经同一提交入口；主线程退出前用“忙任务计数”判断线程池是否静止。

### 进程退出与排空

- 顶层语句执行完后，入口桩调用调度器主循环：驱动全部 fiber 直至静止，并等待线程池在途任务完成。
- 等待线程池的预算默认 `2000ms`，可用环境变量 `XT_SCHED_DRAIN_MS` 覆盖（毫秒，`0` 表示不等待，非法值回退默认）。
- 预算耗尽即放弃等待并返回：**常驻后台任务不会被杀死，也不会阻止进程退出**，其资源由操作系统回收。有限任务在预算内仍会被完整排空。

## 错误与诊断

| 场景 | 诊断 | 性质 |
|------|------|------|
| 异步块循环体内含挂起点 | 编译提示：已整体编译为线程池任务，并建议把挂起移出循环体 | 提示，不中断 |
| 异步块含 `求`/`执`/`输` | 编译提示：已整体编译为线程池任务 | 提示，不中断 |
| 异步块内 `道.收(毫秒)` | 编译错误，建议改用 `选([通道], 超时)` | 编译期中断 |
| `选` 参数不足两个 | 语义错误后终止编译 | 编译期中断 |
| `道.收` 传多于一个实参 | 编译错误 | 编译期中断 |
| fiber 池耗尽（>65535 个活跃 fiber） | 运行时错误并退出 | 硬退出 |
| 定时器堆溢出（>8192 个并发睡眠） | 运行时错误并退出 | 硬退出 |
| 任务句柄被二次 `等待` | 不诊断，返回 `空` | 静默返回值 |
| `尝试` 跨线程/跨异步块使用 | 状态按线程隔离，任务内可捕获 | 可用（共享结果变量属数据竞争） |
| 无 `返` 的异步块 | 结果 `空` | 正常语义 |

## 当前实现限制

- 循环体内的挂起点不能 fiber 化，只能整块降级到线程池（每个此类任务独占一个 worker 线程）。
- `并行` 分支没有闭包环境：外层局部变量在分支内静默求值为 `空`，且无编译诊断。
- `进程.*` 与 `文件.读`/`文件.写` 是阻塞调用但不参与路由判定；与语句级挂起点共存时会阻塞调度器线程。
- fiber 调度是单线程的：fiber 之间没有并行，只有让出；CPU 密集工作必须走线程池（无挂起点的异步块或 `并行`）。
- 定时器与 `选` 的重试粒度均为 `1ms`，`时.睡` 与 `选` 的超时精度不优于该粒度。
- 常驻任务在进程退出时可能被直接丢弃（有界排空），不会收到任何取消信号。
- 未定义：fiber 中途退出的资源回收顺序、任务句柄跨线程传递的可见性、同一任务被并发 `等待` 的结果归属。
- 未定义：递归深度与原生栈耗尽时的行为（进程崩溃）。
- 不做公平性保证：fiber 无优先级、无时间片；一个不主动挂起的 fiber 会一直占用调度器线程，直到它完成或挂起。
