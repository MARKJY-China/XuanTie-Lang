## 〇、对标格局(先说人话)

- **Python(解释型)**:除三个短板外已全面碾压(4~15×)。不值一提,不作宣传对象。
- **NodeJS(V8 JIT)/Java(HotSpot JIT)**:当前**全面落后 2~20×**(拼接最惨)。这是几十年 JIT 工程的功力,诚实面对。
- **Go(编译型)**:整数/递归强一个量级(本机 386 数据还打了折)。

**现实目标分档**:
- 近期(可宣传):**全面超过 Python**——修掉 P1/P2/P3 即达成。
- 中期(里程碑):整数/控制流进入 Node 的 1/2 射程内;fib 递归贴近 Node。
- 远期(不承诺):逼近 Go。**不承诺追平 V8/JIT**——那是 JIT 运行时优化的赛道,我们是 AOT 静态编译,赛道不同。

## 二、短板分析与优化项(按预期收益排序)

### P1 字符串拼接(慢 84×于 Python,1418×于 Node)— 收益最大

- **根因**:`xt_string_concat` 每次调用全量复制(O(n²));且存在**双重复制**——先 `malloc+memcpy×2` 拼临时串,`xt_string_new_len` 再整体复制一次(每字节实际复制 3 次)。Node 快因 V8 的 ConsString(延迟拼接,拼接即指针组合,使用才摊平)。
- **影响场景**:日志/文本生成、模板拼接、大 JSON/CSV 拼装、网络报文构造、UI 动态文本——文本密集型全灭。
- **优化项**:
  1. (快赢,~3×)concat 去双重复制:直接分配目标对象一次拷贝。
  2. (根治方向 A)字符串构建器:循环内追加 O(1) 摊销。
  3. (根治方向 B,对齐 V8)拼接产生"拼接串"节点( rope/ConsString ),延迟到物化(示/写文件/取长度)才摊平——收益最大但动字符串表示,风险高。
- **目标**:≤130ms(追平 Python);冲刺 ≤10ms(Node 量级,需方向 B)。

### P2 字典插入(慢 9.1×于 Python)

- **根因(待 profiling)**:嫌疑按序——① `xt_hash_value` 哈希质量;② 扩容策略;③ 键的字符串化与拼接开销(连带 P1);④ 桶链表退化。
- **优化项**:探针定位后对症:FNV-1a/更快哈希 + 2 倍扩容 + 开放寻址。
- **目标**:≤11ms(2× Python 内);冲刺 ≤5ms(Node/Java 量级)。

### P3 浮点装箱(慢 2.6×于 Python,102×于 Node)

- **根因**:`小数` 运算每次产生 XTFloat 堆分配 + 释放,循环内即 malloc/free 风暴。
- **优化项**:注解 `小数` 的局部变量算术走 raw double(对齐整数 raw_i64 快路径),函数边界再装箱。
- **目标**:≤120ms(贴 Python);冲刺 ≤10ms。

### P4 控制流与调用(分支慢 Node 19.5×、嵌套慢 10×、fib 慢 2.4×)

- **根因(待剖)**:boxed 值的比较/分支每轮脱壳;函数调用参数/返回装箱;循环变量覆盖写的 release 链。
- **优化项**:① 局部注解变量的读改写全 raw 化(与 P3 同源工程);② raw 签名函数(参数/返回皆 整)调用零装箱;③ 循环变量覆盖写的 release 消减(标量判定免释放)。
- **目标**:分支/嵌套 ≤2× Node;fib30 ≤12ms。

## 三、中长期观察项(暂不排期)

- GC/Arena 分配器:对象 churn 场景(短生命周期对象风暴)。
- 方法分派内联缓存(字典方法热点)。
- IO/网络吞吐基准(尚无覆盖)。
- 字符串插值 `#{}` 分配次数(与 P1 联动)。

## 四、测量纪律

1. 优化前后必须复测第一节全表,数据就地更新并标注日期。
2. 单项优化必须附最小 benchmark(放入回归集,防性能回退)。
3. 禁止只贴"提升 N 倍"而无绝对微秒数——绝对值才能跨语言对比。
4. Go 对照数据注意本机 386 打折;若换 amd64 环境需整表重测。
5. benchmark 源文件变更需同步更新本表链接与数据。
