## 8.1 并发模型

玄铁采用 **双层架构**：

| 层级 | 机制 | 说明 |
|------|------|------|
| OS 线程层 | 工作窃取线程池 | 执行 CPU 密集型任务，线程数 = CPU 核数 |
| 用户态调度层 | 无栈状态机 + 调度器 | 管理 I/O 等待任务，就绪队列 + 定时器堆 |

`异步 { ... }` 的执行层由编译器按块内容自动选择（路由规则见 8.1.4)。

### 8.1.1 异步任务

`异步 { ... }` 将代码块作为并发任务执行，立即返回任务句柄。

```text
设 task = 异步 {
    示("任务执行中...")
    时.睡(1000)
    示("任务完成")
}
示("主线程继续执行...")
等待(task)
示("任务已结束")
```

**执行流程**：
1. 编译器统计异步块内的挂起点（`等待`/`收`/`发`/`选`/`时.睡`）位置
2. 仅在语句级 → 编译为无栈状态机（poll 函数 + 状态结构体），`xt_fiber_spawn` 直接提交用户态调度器
3. 循环体内含挂起点 → 整体编译为独立函数，`xt_async_spawn` 提交线程池
4. 主线程执行到 `等待` 或程序末尾时驱动调度器事件循环
5. 任务的 `返` 回值可被 `等待` 取回（无 `返` 则得 `空`）

### 8.1.2 并行执行

`并行 { {块1}, {块2}, ... }` 并发执行多个代码块。

```text
设 results = 并行 {
    { 时.睡(500); 返 "A" }
    { 时.睡(300); 返 "B" }
    { 返 "C" }
}
// results = ["A", "B", "C"]
```

### 8.1.3 行为约定与禁忌（必读）

1. **主线程的 `收`/`发` 默认阻塞**（空等货、满等位）。主线程阻塞期间会顺带驱动 fiber 调度器，不会死锁；但「永远等不到货」的 `收` 会让程序永远停在那里——这不是卡死，是阻塞语义。
2. **fiber 任务的返回值只能取一次**。第二次 `等待` 同一个已完成的 fiber 得到的是 `空`（槽位已回收复用）。需要多次使用的结果请先存进变量。
3. **fiber 内捕获的外层局部变量是 spawn 时刻的值副本**。spawn 之后外层再修改，fiber 内看到的是旧值；fiber 内对它的修改也不会写回外层。需要共享请用通道传递，或改用全局变量。
4. **`等待(fiber)` 会驱动调度器直到全局静止**。若程序里还有长时间睡眠的其他 fiber，`等待` 会等它们一并结束才返回——设计如此，不是挂起。
5. **fiber 句柄上限 65535 个**。正常逐个 `等待` 的程序会触发槽位回收，实际远够；只创建不等待会持续占用槽位。
6. **不要把「循环内挂起」当成零成本并发**。它独占 worker 线程；线程池容量（CPU 核数量级）内没问题，成百上千个这种任务会退化。海量并发场景请把挂起点移到循环外（语句级），走 fiber。
7. **嵌套在回调函数内的异步块捕获外部变量**仍是已知局限。

### 8.1.4 自动路由规则（重要）

编译器统计异步块内的**挂起点**（`等待`、`收`、`发`、`选`、`时.睡`）出现的位置：

| 挂起点位置 | 执行层 | 代价 |
|-----------|--------|------|
| 仅在语句级（不在任何循环体里） | fiber 调度器 | 微秒级切换，几乎零占用 |
| 任意挂起点出现在循环体（`当`/`遍历`/`循`）内 | 线程池 | 运行期间独占一个 worker 线程 |

路由到线程池时编译器会给出诊断提示，例如：

```text
编译提示: 异步块检测到 1 个循环内挂起点(等待/收/发/选/时.睡),已整体编译为线程池任务...
```

**为什么循环内挂起要走线程池**：fiber 是无栈状态机，挂起恢复依赖编译期生成的状态跳转；循环体内的挂起恢复需要保留循环索引等局部状态，当前实现选择把这类代码放到真正的 OS 线程上执行——阻塞语义天然正确，但会占用一个 worker。

**推荐模式**：

```text
// ① 语句级挂起 → fiber,最轻量
设 任务 = 异步 { 时.睡(100); 返 42 }
设 结果 = 等待(任务)          // 结果 = 42

// ② 循环内挂起 → 自动路由线程池,语义正确,放心写
设 消费者 = 异步 {
    当 真 {
        设 货 = 通道.收()     // 阻塞等待,不占 fiber
        示("收到: " & 货)
    }
}

// ③ 非阻塞试探:用 选 的超时 0,而不是直接 收
设 idx = 选([通道], 0)        // 立即返回:有货返下标,没货返 -1
```

## 8.2 通道

`道(容量)` 创建带缓冲的并发通道。v0.3 起支持**阻塞收发**（条件变量）。

### 8.2.1 基本用法

```text
设 ch = 道(4)      // 容量为 4 的通道
ch.发("hello")     // 非阻塞发送（满则丢弃）; 状态机中为阻塞发送
ch.发("world")
设 msg = ch.收()   // 非阻塞接收（空则返回空）; 状态机中为阻塞接收
示(msg)
```

### 8.2.2 阻塞收发（状态机内）

在 `异步` 块内使用 `.发()` / `.收()` 时，编译器自动使用阻塞版本：

```text
设 ch = 道(3)

设 consumer = 异步 {
    设 sum = 0
    设 i = 0
    当 i < 3 {
        sum = sum + ch.收()  // 阻塞等待，不占 OS 线程
        i = i + 1
    }
    示("Sum: " & sum.转字())
}

设 producer = 异步 {
    ch.发(1)
    ch.发(2)
    ch.发(3)
}

等待(producer)
等待(consumer)
```

### 8.2.3 多通道选择（选）

`选(通道数组, 超时毫秒)` 等待多个通道中第一个就绪的，返回通道索引。超时返回 -1。

```text
设 fast = 道(1)
设 slow = 道(1)

设 sel = 异步 {
    设 idx = 选([fast, slow], 5000)
    若 idx == 0 { 示("fast 就绪") }
    抑 idx == 1 { 示("slow 就绪") }
    否 { 示("超时") }
}
```

> **主线程泵送语义**：主线程在 `选` 等待期间会驱动用户态调度器（与 `收`/`发` 的无限等待一致），因此发送方是 fiber（无循环挂起的异步块）时数据也能正常到达。代价：**fiber 内有长睡眠或线程池有在途任务时，`选` 的返回可能晚于你给的超时毫秒数**（等待会持续到 fiber 跑完一轮）；超时到期仍未就绪才返回 -1。如果你需要严格守时的多路等待，把发送方移出 fiber（用含循环挂起的异步块走线程池），或把超时拆成多次短轮询。


### 8.2.4 线程安全

通道操作（`发`/`收`/`选`）已加互斥锁+条件变量保护，多线程并发安全。

## 8.3 HTTP 请求

`求(url)` 发起 HTTP GET 请求，返回 `结果` 对象。

```text
设 resp = 求("http://api.example.com/data")
若 resp.成功 {
    示("响应: " & resp.值)
} 否 {
    示("请求失败: " & resp.错误)
}
```

**当前支持**：HTTP/1.1 GET，自动解析 host:port/path，返回响应体文本。  
**暂不支持**：HTTPS、POST/PUT 等方法、自定义 Header。

## 8.4 TCP 网络

### 8.4.1 服务端（监听）

`听(端口, 回调函数)` 在指定端口启动 TCP 监听。

```text
听(8000, 函(流) {
    示("新连接！")
    流.写("欢迎！\n")
    循 {
        设 data = 流.读()
        若 data == 空 { 断 }
        示("收到: " & data)
        流.写("回显: " & data)
    }
})
输("按回车停止...")
```

### 8.4.2 客户端（连接）

`连(地址)` 连接到 TCP 服务端，返回 `结果`。

```text
设 conn = 连("127.0.0.1:8000")
若 conn.成功 {
    设 流 = conn.值
    流.发("hello")
    示("服务端回复: " & 流.读())
    流.关()
} 否 {
    示("连接失败: " & conn.错误)
}
```

### 8.4.3 Socket 方法

| 方法 | 说明 |
|------|------|
| `.读()` | 读取数据，返回字符串或空 |
| `.写(内容)` | 写入字符串 |
| `.发(内容)` | 同 `.写()` |
| `.关()` | 关闭连接 |

## 8.6 线程安全速查

| 组件 | 线程安全性 | 说明 |
|------|-----------|------|
| 通道 (`道`) | **安全** ✓ | `xt_chan_mutex_t` + 条件变量全程持锁 |
| 通道（阻塞收发） | **安全** ✓ | 条件变量等待，不占 OS 线程 |
| 选 (`选`) | **安全** ✓ | 轮询+条件变量，超时安全 |
| 异步 (`异步`) | **安全** ✓ | 状态机 poll 函数由调度器单线程调用 |
| 并行 (`并行`) | **安全** ✓ | cloneEnv 隔离 |
| Socket I/O | **安全** ✓ | 每个 socket 独立，无共享状态 |
| ARC | **安全** ✓ | atomic_fetch_add/sub |
| 调度器 | **注意** ⚠ | 线程池回调唤醒 fiber，无锁竞态（当前单线程未触发） |
| 全局变量 | **不安全** ✗ | 用户代码需自行加锁 |
| 弱引用 | **安全** ✓ | `g_weak_mutex` 保护 |
