# 进程

**子进程标准输入管道。** 启动外部命令，分多次写入原始字节，关闭输入发送 EOF，再等待退出。适合向 ffmpeg 等从 stdin 消费的程序直接喂数据。

## 函数

| 调用 | 返回 | 说明 |
|------|------|------|
| `进程.启动(命令)` | `结果` | 经系统 shell 启动子进程；成功时 `.值` 为进程句柄 |
| `进程.写(句柄, 数据)` | `结果` | 完整写入字符串或 `字节`；成功时 `.值` 为 `真`，不追加换行，不做编码转换 |
| `进程.刷新(句柄)` | `结果` | 将标准输入的缓冲刷入操作系统管道 |
| `进程.关闭输入(句柄)` | `结果` | 关闭 stdin 发送 EOF，但不等待；可重复调用 |
| `进程.等退出(句柄)` | `结果` | 尚未关闭时先发送 EOF，再等待退出；可重复调用，`.值` 为实际退出码 |

## 示例

```text
设 开 = 进程.启动("ffmpeg -y -f rawvideo -pix_fmt rgb24 -s 16x16 -r 30 -i - out.mp4")
若 非 开.成功 { 终 1 }
设 子 = 开.值
设 帧 = 字节(16 * 16 * 3)

设 像素 = 0
当 像素 < 16 * 16 {
    帧.追加(像素 % 256)
    帧.追加(0)
    帧.追加(255 - (像素 % 256))
    像素 = 像素 + 1
}
进程.写(子, 帧)
进程.写(子, 帧)
进程.关闭输入(子)
设 完成 = 进程.等退出(子)
若 完成.成功 且 完成.值 == 0 { 示("编码完成") } 否 { 示("编码失败") }
```

## 退出码与错误

- `进程.等退出` 的 `.成功` 表示**关闭管道和等待操作成功**，不是子进程退出码为 0。必须另查 `.值`。
- 子进程主动终止时，操作成功的 `.值` 仍可能是非零；正常信号退出按 `128 + 信号号` 报告。
- 无效句柄、参数类型错误、往已关闭管道写入、刷新／关闭／等待失败，都返回失败 `结果`，不会伪装成成功。
- 启动成功只代表 shell 与管道已经建立；找不到命令通常要在写入或等待阶段才能观察到非零退出码。

## 平台与边界

- 命令与 `执()` 一样交给 shell：Windows 为 `cmd.exe /c`，macOS／Linux 为 `/bin/sh -c`。不可信输入必须视为命令注入风险。
- stdout 和 stderr 继承宿主，不走 `执()` 的退出后统一捕获。
- Windows 使用二进制管道，`0x00`、`0x0A`、`0xFF` 不走文本转换；POSIX 对先退出的子进程按写入错误处理，不会因 `SIGPIPE` 直接杀死宿主。
- 写、刷新、关闭、等待均为同步阻塞；同一进程句柄不得并发操作。
- 句柄由 ARC 回收管理；未显式等待时会先关输入再等待，避免遗留运行中的子进程。仍应显式关闭并等待，以获得错误与退出码。
