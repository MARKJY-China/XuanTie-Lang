

# 解

**JSON 反序列化。把 JSON 文本解析成字典/数组。**

```text
设 数据 = 解("{\"名称\": \"玄铁\"}")
示(数据["名称"])   // 玄铁
```

## 你可以……

- **解析后当字典用**——键用引号串下标：

```text
设 消息 = 解(体)
若 消息.包含?("method") {
    示(消息["method"])
}
```

- **解析数组**：

```text
设 列表 = 解("[1, 2, 3]")
示(列表[1])   // 2
```

- **解析小数与科学计数法**——带 `.` 或 `e`/`E` 的数字解析成 `小数`（保真，不截断）：

```text
示(解("3.14"))            // 3.14（小数）
示(解("0.1"))             // 0.1（小数）
示(解("1e3"))             // 1000（小数）
示(解("2E6"))             // 2000000（小数）
示(解("9007199254740993")) // 9007199254740993（整，精确，不转 double）
```

- **配 `求` 解析接口返回**：

```text
设 r = 求("http://api.example.com/data")
若 r.成功 {
    设 数据 = 解(r.值)
    若 数据 != 空 { 示(数据["名称"]) }
}
```

## 注意

- 非法 JSON、空串都解析成 `空`——取用前先判空。
- JSON 的 `null` 也解析成 `空`，与失败同值；需要区分时核对原文，或改用下节的 `试解`。
- 输入开头的 UTF-8 BOM（`EF BB BF`）会跳过，带 BOM 的合法 JSON 可正常解析（v1.0-rc.6-dev.5，#151）。
- **小数保真**：带 `.`/`e`/`E` 的数字走 `strtod` 解析，`0.1`、`1e3`、`2e6` 均正确；十进制上溢（如 `1e400`）**整份解析失败**，不产出 `Inf`。
- **整数精确**：纯整数 token 按 i64 精确解析，大整数（如 `9007199254740993`）不转 double；超出 `整` 的可表示域 ±(2^62-1) 时**整份解析失败返回 `空`**，并在 stderr 打一行诊断（不静默截断，#150/#153）。
- **语法从严**：尾部多余内容（`"123abc"`）、容器缺元素/缺逗号（`"[1,]"`、`"{\"a\":}"`）、字符串未闭合、未知转义、数字残缺（`"1."`、`"-"`）都视为非法 JSON，整份返回 `空`，不再把半截结果当合法值。

## v1 契约：三态反序列化（`试解`）

`解()` 按兼容契约把「空串 / 非法 JSON / 合法 null」**都**返回 `空`，无法区分。需要区分时用三态 API：

```text
设 r = 试解(文本)
若 r.成功 {
    // 解析成功；r.值是解析结果（源文本是 JSON null 时 r.值 也是 空，但 r.成功 为 真）
} 否 {
    // r.错误 是明确原因文本
}
```

返回值与 `解` 的对照（写死）：

| 输入 | `解(文本)` | `试解(文本).成功` | `试解(文本)` 的 `.值` / `.错误` |
|---|---|---|---|
| 空串、仅空白/BOM | `空` | 假 | `.错误` 以 `空输入` 开头 |
| 非法 JSON | `空` | 假 | `.错误` 以 `非法 JSON` 开头（含字节位置） |
| 数字越界（整域/浮点上溢） | `空` | 假 | `.错误` 以 `数值越界` 开头（含具体数字） |
| 合法 `null` | `空` | **真** | `.值` 为 `空` |
| 合法值 | 解析值 | 真 | `.值` 为解析值 |

- `解()` 的旧行为（三者都返回 `空`）是**兼容契约，写死不改**。
- `试解` 不向 stderr 打诊断；失败原因只在 `.错误` 里。`解()` 的数值越界仍保留 stderr 一行诊断。
- 非字符串入参会触发与 `解` 相同的运行时类型守卫，明确报错退出（不可捕捉）。
- `试解` 是编译器内建名，直接调用，无需 `外 函` 声明。
