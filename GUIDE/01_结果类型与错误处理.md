# 结果 (Result) 类型与错误处理

> 对标版本：玄铁 v1.0-rc.5（issue #110 运行时错误定位、issue #113 硬错误可捕获与 尝试 表达式形态）。

玄铁的错误处理分两层：

- **主路：`结果` (Result) 类型**——借鉴 Rust 的设计，把可预期的失败编码成返回值，由调用方显式判断。可预期的失败都用这一层，本文重点介绍。
- **兜底：`尝试` / `捕捉`**——接住运行时故障（除零、溢出、成员访问空值、索引非对象等），避免进程直接退出。它只兜"编程错误"这一层，不替代 `结果`。

并非所有运行时错误都可捕：按「宁可报错退出也不静默跳过」原则，堆损坏、`解(非字符串)` 等运行时守卫、以及**跨函数**发生的成员/索引/方法硬错误仍是硬退出。完整清单、错误位置格式与 `尝试` 表达式形态见 [关键字/尝试](关键字/尝试.md)。

## 概念与底层结构
`结果` 是一个内置的泛型数据容器。在底层的 C 运行时 (`xt_runtime.h`) 中，它被定义为一个名为 `XTResult` 的结构体，包含三个核心字段：
1.  **状态位 (`is_success`)**：标记这个结果是成功还是失败。
2.  **成功值 (`value`)**：如果成功，这里存储具体的返回值。
3.  **错误信息 (`error`)**：如果失败，这里存储错误原因（通常是一段字符串）。

## 如何创建 `结果`
在代码中，你可以使用内置函数 `成功()` 和 `失败()` 来打包返回值：
```xuantie
函 除法(a, b) {
    若 b == 0 {
        返 失败("除数不能为零")
    }
    返 成功(a / b)
}
```

## 如何消费 `结果`
当你调用一个返回 `结果` 的函数时，你有两种处理方式：

### 方式一：手动解包（严谨）
```xuantie
设 结 = 除法(10, 2)
若 结.成功 {
    示("计算结果: " & 结.值)
} 否 {
    示("发生错误: " & 结.错误)
}
```

### 方式二：使用错误冒泡操作符 `?`（快捷）
如果你不想在每一层都写 `若 结.成功`，可以在表达式后加上 `?` 操作符。
```xuantie
设 值 = 除法(10, 2)? 
// 👆 编译器遇到 ? 会自动展开为：
// 如果成功，把 "值" 赋给左边；
// 如果失败，立刻终止当前函数，并将这个 "失败" 结果 return 给上一层调用者。
```
当然，你也可以这样写：
```xuantie
设 值 = 除法(10, 2)
设 真值 = 值 ?
// ↑ 标识符允许以 ? 结尾(如 存在?),变量名与 ? 之间必须留空格,否则会被词法器读成一个标识符
```

## 运行时故障兜底：`尝试` / `捕捉`

```xuantie
尝试 {
    设 无 = {"x": 1}["不存在"]
    示(无.长度)            // 成员访问空值 → 进 捕捉
} 捕捉 (e) {
    示(e["消息"])          // [D:\项目\主.xt:3:8] 对非对象值(整数/布尔/空)访问成员 '长度'
}
```

- **可捕**：整数/小数除零、求模除零、整数溢出、注解参数类型不匹配，以及**同一函数 `尝试` 块内**的成员访问空值、未知成员、索引非对象、负索引、方法缺失。
- **硬退出**（诊断后 exit 1，`捕捉` 兜不住）：堆损坏/非法指针、`解(非字符串)` 等运行时守卫、无 `尝试` 保护的同款硬错误，以及硬错误发生在被调函数而 `尝试` 在调用方（跨函数不转异常）。
- **不是异常**：正向索引越界/字典缺键返 `空`；`文件.读` 等 I/O 返 `结果` 容器。
- 运行时错误统一打印 `运行时错误 [文件:行:列]: ...`；被捕获时 `错误["消息"]` 带 `[文件:行:列] ` 前缀（issue #110）。
- `尝试` 也可作表达式取值（issue #113）：默认取块尾表达式；可在块内用 `产出 表达式` 从任意位置提前给出值。
