# 玄铁铸造厂版本史(versionLog)

玄铁铸造厂 SemVer 框架:`主版本.次版本.修订号`。

- 主版本:产品里程碑(如"用玄铁 UI 库重构铸造厂"即为 v1 的门槛)。
- 次版本:功能集更新(v0.1 基础壳 → v0.2 → v0.3 控件设计器 …)。
- 修订号:向后兼容缺陷修复/小更新。

对标关系:铸造厂版本独立演进,不随玄铁语言版本号走;每个版本条目注明当轮实测对标的玄铁工具链状态。

## v0.4.0 (2026-10-04)

智器对话与 Agent 体验强化版本。在 v0.3.1 之后完成:上下文自动压缩阈值改按模型上下文配置
(自定义提供商设置项 + 官方后台经 /api/ai/config 下发)、SSE 流中断三层恢复(非流式降级补全/
「继续」按钮/反馈链路)、流中断根因修复与全链路诊断体系、玄铁基础认知注入(后台可编辑、
离线回退内置)、/compact 命令、AI 文件访问三态权限(禁止/询问/允许)、文件树多选与

#### 流中断恢复与反馈(2026-10-04)

- **非流式降级补全**:流被截断(SSE 结束未收到 finish_reason)且尚未发出正文/工具调用时,
  adapter 自动把同一请求改 stream:false 重取完整结果并补发为等价流事件,上层无感继续
  (思考内容允许重来——失败尝试不进模型历史,只影响 UI 展示);已发正文/工具调用时不做
  补全(重生成内容不可拼接),按截断错误上抛。
- **「继续」按钮**:流中断/传输错误的错误气泡旁提供「继续」——把已收到的部分内容作为
  引用块合成续写指令,模型从中断处接着写、不重复已输出部分(部分内容过长时留头留尾)。
- **反馈链路**:本会话流中断达 5 次时,错误气泡追加作者联系方式(社区后台
  ailm_contact_name/ailm_contact_value 经 /api/ai/config 下发)与「反馈问题」入口——
  就地弹窗提交,走社区 /api/feedback(kind=bug,自动附模型/通道/错误/会话上下文),
  管理员后台「反馈」页可见,并邮件通知全部管理员账号(本轮新加)。
- **官方库源码只读放行**:read_file/list_files 白名单加入环境快照探测到的官方库目录
  (lib/,只读;write_file 仍限工程根)——AI 可直接读库源码查证 API 签名;persona 同步
  写入"库用法先 docs_search,再读库源码查证"。

- **会话重建历史注入(修复"重新生成后模型失忆")**:Agent 模式下回退/重新生成/换模型档位
  都会重建 DSH 会话(历史不可注入),原先重建后模型只看得到新消息——实测出现"重新生成后
  AI 称这是会话第一条消息";现在重建统一注入<先前会话记录>块 = 既有压缩摘要 + 历史回放
  (单条 1200 字截断、总量 16K 受限、头部保最早 2 条、排除即将发送的末条用户消息),
  ensureSession 在无显式记录时还会向面板兜底取回放(覆盖换模型/换档位等全部重建路径,
  顺带让重启恢复的历史会话在 Agent 模式下也能带着前情继续)。

背景:实测自定义通道(DeepSeek 直连)出现"SSE 流结束但未收到 finish_reason"且长思考后
被截断时无任何恢复路径;另实测 AI 在远离玄铁源码的工程里反复试探库 API 写法(读不到库
源码),本次一并处理。

#### 玄铁基础认知注入(2026-10-04)

  自定义通道简单对话由客户端插 system 消息注入;官方通道简单对话由服务端内置同源常量

#### 交互增强与权限体系(2026-10-04)

  聊天记录落一条居中分割提示(「上下文正在压缩…」→「上下文已自动压缩」),不进对话、
  不发送给 AI;手动压缩保留窗口收窄为最近 2 条(压得更彻底),共用自动压缩管线。
- **AI 文件访问范围(三态)**:「管理 AI 提供商」弹窗新增「AI 文件访问范围」——禁止(默认,
  越界直接拒绝)/询问(越界弹审批卡片,允许一次/拒绝;拒绝与关面板 fail-closed)/允许(自由
  访问任意路径,高风险);作用于 read_file/list_files/write_file 的路径解析(write 根内仍限
  工程根,工程外按同一策略)。
- **文件树多选**:单击选中并打开、Ctrl 点选切换、Shift 连选、空白处拖拽框选(橡皮筋);
  右键落在未选中项先单选该行;右键菜单新增「添加到对话」(多选时批量添加 N 项)。
- **「添加到对话」全场景接入**:引用 chip 泛化为 code/终端/构建/问题/路径五类——终端与
  构建输出选中文本后浮出「添加到对话」小按钮;问题面板双击或右键添加(格式化「错误/警告
  + 消息 + 位置」);文件树右键添加文件/目录路径;发送时按来源以不同措辞拼为引用块。
- **「打开最近工程」**:文件菜单新增 VSCode 式子菜单——菜单系统支持 `›` 悬停展开的子菜单与
  动态内容(每次打开菜单时求值);最近打开的工程(最近在前、去重、上限 10,存设置
  recentWorkspaces)直接点选打开,目录已不存在时提示并自动移出列表;末尾含「清除最近
  打开记录」。
- **「以管理员身份重启」**:文件菜单底部新增,复用提权重启命令(先 is_elevated 预检,
  已是管理员时仅提示、不重复重启)。
- **流式通道去总超时(修复"后台跑长任务流中断高发")**:`http_stream` 的 reqwest 客户端原带
  300s 总超时——长思考/大输出的正常长流必然撞线被拦腰切断(放后台跑长任务时尤甚);

- **会话实时保存**:思考段结束、工具执行终态(含被拒)即把"直播中的进行中消息"并入

  进程意外退出/切工程会丢整轮现场。
- **工具参数流式预卡**:write_file 的大文件内容在流式生成期(可达几十秒)此前 IDE 侧无
  任何提示(正式工具卡要等参数生成完才出现)——现首个 tool-call 增量即立「正在编辑
  <路径>…/正在生成命令…」准备中卡(titleEl 随 path/command 闭合逐步精确),
  正式 tool/call 事件到达时按 callId 退场换常规卡。

#### 环境自检与 runtime 预编译(2026-10-04)

- **玄铁环境自检(preflight)**:打开工程后台自动跑内置探针(Rust 内嵌 `preflight_probe.xt`,
  产物落 app 数据目录 preflight/)——覆盖编译器可用性(编译+运行)、字符串插值、数组、
  元素字段引用回写、遍历写回、删、下标写、抑分支、数学、顶层变量函数内写回等基础语义,
  输出 `[自检] 键=值` 事实行;结果注入环境快照(附"直接采用,不要再写探针/冒烟测试"纪律),
  免去 AI 开局自写探针测试烧 token;任一项未通过 → 面板黄色警告引用提示。
- **轮次开始等待自检**:AI turn 开始时若自检未完成,状态行先显示「正在校验本地玄铁环境…」
  而非"连接模型中/思考中",完成后再进入常规状态(结果随之进快照)。
- **校验可见化**:状态栏 LSP 项右侧新增校验徽标——校验中橙灯「本地玄铁环境可用性校验中」、
  异常红灯「本地玄铁环境异常」、通过绿灯「本地玄铁环境正常」(5 分钟后自动隐藏);
  **双击徽标打开 CI 式校验控制台**(浮层:阶段分隔行 + [编译]/[探针] 输出逐行实时滚动——
  Rust 侧子进程 stdout/stderr 逐行经 `preflight-progress` 事件流出),不再"静默跑、前端无感"。
- **runtime 预编译 .o(修复每次编译重编 C 的 7 秒开销)**:build/env/runtime 补上
  xt_runtime/xt_threadpool/xt_net/xt_tls 四个预编译 .o(与发行脚本 make_pkg.sh 同款
  clang 命令;编译器本就优先 .o、回落 .c)——本机实测 `xtc tie` 从 7.2s 降至 1.8s。
  自检顺带记录一条易猜错的语义事实:`数学.取整` 为向下取整(floor),取整(-2.7)=-3。

#### 流中断根因修复与诊断体系(2026-10-04)

- **根因:社区代理总超时(官方通道)**:`/api/ai/agent/chat` 与 `/api/ai/chat` 的上游
  http.Client 原带 180s 总超时——长思考/长输出的正常 SSE 流总时长越过 180s 即被 Go 侧
  掐断,IDE 表现为"流中断:未收到 finish_reason"(实测 60~120s 思考后高发)。现改为包级
  aiUpstreamClient:仅约束连接(10s)与首响应头(60s),响应体不设总时限。
- **Rust 读流端诊断**:http_stream 统计块数/字节/总时长/末次数据时间;EOF 且未收到 [DONE]
  时发 warn 事件("上游连接在流中途结束…末次数据距今 N ms")并附 stat 统计事件——
  "上游断连"与"正常结束"此前在客户端完全不可区分。读空闲超时放宽至 300s。
- **诊断日志永不静默**:日志总线 warn/error 级不再受"开发者模式"开关限制;错误气泡新增
  「复制诊断」按钮,一键复制 AI 链路日志(含断流原因/流统计)。
- **诊断可用性三修(首份导出实测反馈)**:①日志分池——关键(warn/error,保底 200 条)与
  普通(debug/info,300 条)隔离,逐块 SSE debug 不再挤掉断流原因(实测教训:0.26 秒的
  原始数据块即可灌满单池全部缓冲,导出毫无线索);②导出优化——关键事件全列置顶、普通
  日志同类折叠(≥5 条折一行)、附导出时刻;③降噪与静默可辨——transport 逐块日志改
  「首块+每 100 块抽样」、adapter 逐块 chunk 摘要删除,新增双静默监控(transport
  30s 无数据 → warn 日志;面板状态行 20s 无增量 → 追加"(数据流静默 Ns)")。

#### Harness 反馈落地(2026-10-04,来自铸造厂 AI 自述 + KimiK3 分析)

- **环境卡升级**:系统提示词新增「编译与运行命令」段(xtc tie / xtc pao 编译即运行 /
  xtc tie -jc 仅检查 0.5 秒 / -sc 指定产物)与「可写范围与禁区」段(工程根可读写、
  临时/探针文件只许放 <工程>/.foundry/、库与文档只读、工程外侧越界策略)——消灭
  "这台机器的工具链长什么样"的一整类探测往返。
- **提示词前缀字节稳定(吃缓存)**:快照去掉"工程内顶层 .xt 文件"列表与自检耗时等易变项
  (前缀一变即击穿提示词缓存;实测缓存命中 84%)。
- **docs_search 块返回**:命中行扩展为"所在章节"(上遇标题停限 40 行、下遇标题停限 60 行),
  单次检索即可获完整上下文——此前单行命中必然触发第二次 read_file。
- **example_search 新工具**:检索本地官方文档的 ```xuanti 完整代码块(按命中数排序,
  标来源与行号)——"模板是拷贝-改写器";AI 需要"怎么写"时先抄示例改。
- **check_code 新工具 + write_file 自动检查**:代码写 .foundry/ 临时文件 → `xtc tie -jc`
  (或 `xtc pao` 试运行)→ 返回输出 → 删除临时文件;write_file 落盘 .xt 后自动跑 -jc 并把
  编译器结论附在工具返回值里——错误从"下一轮编译"提前到"写下即知",且永不污染工程根
  (实测教训:残留 _captest.xt)。
- **认知块补"常见错写对照表"**:否/elif→抑、添加/push→追加、len()→.长度、print→示 等
  约 20 条训练先验抗体(均为已验证事实)+ 保留字全表。
- 背景:作者让铸造厂 AI 自我剖析"每次 demo 都在查什么",结论"消耗的不是学玄铁,而是
  消除不确定性"(命名/签名/归属/工程接入);KimiK3 补充"环境卡最便宜收益最快""报错即文档
  应升 P0""114 测试单元是现成语料"等。本轮落地其中的纯 IDE/Harness 项;编译器报错增强
  (E1042 候选修复+文档锚)、LSP 三工具(候选查签名/查符号/列成员)与编译器测试语料索引
  需动 xtc/xt_lsp(自举验证),待独立排期。

#### Agent 模式媒体支持(2026-10-04)

- **Agent 模式支持图片/视频输入**:DSH 的 `session.send` 只收文本、附件服务未 vendor——
  改为**适配器直发注入**:面板把本轮附件交给 adapter,组装 OpenAI 请求时注入最后一条
  user 消息(与简单对话同一多模态格式 image_url/video_url + data URL);DSH 会话历史仍只

  (官方=后台 ailm_vision/ailm_video;自定义=提供商自报)对两种模式一致。

  铁铺后续仅保留匿名索引/下载,发布令牌改由社区派发;本轮未改动社区/铁铺服务端。

- **LSP 悬停/跳定义/大纲全空根因修复(URI 盘符大小写)**:monaco(vscode-uri)的

- **账号会话持久化修复**:此前 Cookie 头只发裸令牌值,缺 `xt_session=` 名字,
  服务端 `c.Cookie()` 解析不到 → 启动校验必失败 → 每次开 IDE 都要重新登录;
  现按名发送。新增 **7 天登录有效期**(本地 loginAt 时间戳闸门,超期强制重新登录;

#### 功能范围(与 ide/AGENTS.md 的 v0.1 纪律一致)

- **文件树**:目录全量加载(限深限量),右键新建文件/文件夹、重命名、删除(回收站);`.xt` 高亮标识。

  `tie -sc <应用缓存目录> → 运行产物`(PowerShell 串联,退出码判断);运行走独立终端会话,可交互、可停止。
