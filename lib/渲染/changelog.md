# 渲染库 Changelog

## v1.3.2

**新增**

- **Linux 双后端 raylib 静态库**:`libraylib.linux-amd64.a`(GLFW Wayland+X11 双后端,raylib 6.0)——Wayland 会话(GNOME/KDE 默认)下窗口为 Wayland 原生,不再经 XWayland 兼容层(issue #60 修复方向 1 落地)。GLFW 运行时优先 Wayland、自动回退 X11,X11 会话与 Windows/darwin 不受影响。构建配方见同目录 `构建-linux-raylib.sh`(可复现构建,含 Wayland 后端验证方法)。

## v1.3.1

**新增**

- **合成音效(零资产发声)**:`合成音效(频率, 时长毫秒)` —— 桥内合成 16 位单声道正弦 PCM(22.05kHz,10ms 淡入淡出免咔哒,非法入参钳制),返回与文件音效**同一句柄池**的句柄,播放/释放直接复用 `播音效`/`释音效`。做游戏音效不再必须携带 wav 资源。合成缓冲在 `释音效` 时释放(raylib `LoadSoundFromWave` 的拷贝语义头文件未言明,保守保活)。

**修复**

- **`xt_get_float` 整数容错**:此前只认 XFloat 对象,库的"小数"形参传整数(如 `暂停(1)`)时**静默归 0.0**——所有小数形参函数的隐性坑(2026-10-04 狗粮实测)。现标记整数按数值返回;3D 段临时的 `xt_get_num` 随之合并删除。

**验证**

- 桥预编译对象重建(Windows x86_64,`clang -target x86_64-w64-windows-gnu -O2`);合成音效句柄的创建/入容器/释放/非法入参钳制经无窗口探针验证;渲染回归用例 95 通过。

## v1.3.0

**新增**

- **3D 渲染通道**：库自述一直是「2D/3D」，但此前绑定/桥里**没有任何 3D API**（无相机、无 3D 图元）。本版补齐 raylib 核心 3D：
  - `设置相机3D(眼x, 眼y, 眼z, 靶x, 靶y, 靶z, 视场)`、`进入3D()` / `退出3D()`
  - 图元：`绘立方体` / `绘立方体线` / `绘球体` / `绘球体线` / `绘地面网格` / `绘直线3D` / `绘点3D`
  - 矩阵栈（旋转/平移图元）：`推矩阵` / `弹矩阵` / `平移3D` / `旋转3D`（rlgl 通道，桥内显式声明原型，符号在随包 libraylib.a 中 llvm-nm 实测）
  - 坐标约定与 raylib 一致：Y 轴向上、右手系；相机 up 固定 `(0,1,0)`、透视投影。
- 桥内新增 `xt_get_num` 取参：**标记整数容错转 double**——既有 `xt_get_float` 只认 XFloat 对象，`1` 与 `1.0` 混用时整数侧会静默归零（本版新增函数一律不受此影响；既有函数的同款隐患待后续统一）。

**验证**

- 新增 3D 狗粮试作《宝石猎手》（第三人称收集玩法，纯 raylib 图元 + 中文 HUD 字体），Windows x86_64 编译通过并人工运行验收；试作同时产出一份语言/库改进观察清单（见仓库 temp 试作目录，未入库）。
- 桥改动为纯新增，未触碰既有 2D/字体/纹理/音频路径；随包预编译渲染桥在打包时由 `make_pkg.sh` 现编，发行物自动带上本版。

## v1.2.7

**修复**

- **TTC 字体通道修复（issue #43；由 @k4m7v2pz 贡献 PR #48）**：`.ttc` 直载此前**必然失败**——raylib 硬编码 `stbtt_InitFont(..., 0)`（`rtext.c`），不识别 ttcf 容器；失败时静默回退 raylib 默认字体（glyphCount=224 非 0），形成「句柄非 0 但中文全是 `?`」的伪成功。现改为：解析 ttcf 容器 → 把首 face 重组为独立 ttf（表记录 offset 改写为相对新文件头；TTC 的 offset 以**文件头**为基准——OpenType 规范，Windows 14 款自带 TTC 与 Apple 实测一致，探测双基准兜底）→ 交 raylib 加载。**顺带修好 Windows/Linux 的 `.ttc` 加载**（同一根因）。
  - 伪成功消除：失败检测改「`glyphCount == 0` 或纹理即默认字体」，真失败返回 0 且**不占句柄槽位**。
  - CFF（CID-keyed，stb 不支持）拦截：苹方/冬青黑体这类 OTTO 首 face 的 ttc 直接返 0；名字命中时**自动兜底黑体**，不再崩。
  - macOS 路径表修正：宋体 → `Supplemental/Songti.ttc`；苹方在 AssetsV2 动态 asset 目录（hash 随系统版本变）→ 运行时 glob 探测。
- **畸形字体文件边界加固**：ttc 字段取自文件内容，伪造值可令原 32 位边界算式回绕而越界读——实测两处段错误（OTTO 探测处的 `(int)` 转换、重组函数三处无符号回绕带）；全部改用 `size_t` 安全比较，12 例畸形变体扫描全部优雅返回 0 不崩。
- **更正 v1.2.6 的声明**：v1.2.6 changelog 与 `GUIDE/09` 写着「`.ttc` 可用」，该说法当时**未经运行时验证、实际不成立**（直载必失败，见上）；`.ttc` 真正可用自本版起。

**验证**

- Windows 侧以 raylib 6.0 同源 stb_truetype（v1.26）A/B：原始 ttc 走 offset 0 加载失败（`InitFont=0`，复现 raylib 行为）；重组产物 `InitFont=1` 且 `中/A/あ/韦` 字形命中（微软雅黑/宋体/微软正黑/游明朝四款实测）；重组产物 25/25 表与源逐字节一致、无越界。
- macOS 侧由报告者在 macOS 26.6.2 / M3 实测：苹方/冬青黑体/STHeiti Light.ttc 中文正常（CFF 自动兜底黑体），不存在字体返 0（伪成功消除）。

## v1.2.6

**修复**

- **macOS/Linux 补上系统字体通道（issue #43）**：`加载系统字体(字体名, 字号)` 此前只有 Windows GDI 实现，非 Windows 平台直接返回 0 → macOS 上没有任何系统字体可用，加上 `绘文字()` 的默认位图字体只有 ASCII，中文只能显示为方块（Windows 与 macOS 能力不对等）。现非 Windows 平台改为「系统字体名 → 系统自带字体文件 → 经既有 `XT_LoadFont` 码点通路载入」，句柄语义、绘制与释放路径与 Windows 完全一致：
  - 名字命中表（`苹方`/`PingFang`、`黑体`/`Heiti`、`冬青黑体`/`Hiragino`、`宋体`/`Songti`、`楷体`/`Kaiti`；Linux 为文泉驿/Noto）则用之；
  - 名字里带路径分隔符或字体扩展名时按**路径**直用（`加载系统字体("/某处/字体.ttc", 28)` 成立）；
  - 都没命中则按表内顺序取第一个存在的系统 CJK 字体（与 Windows 的字体回落同义），一个都不存在才返回 0（绘制回退 raylib 默认字体，不静默假装成功）。
- 文档纠正：`GUIDE/09` 此前写着「不支持 `.ttc`」，与实测不符 —— `.ttc` 可用，按容器内第 1 个 face 解析（macOS 自带字体多为 ttc）。

**实现说明**：解析函数与载入实现体刻意放在平台宏之外，只依赖共享 API，因此在 Windows 构建里也会被编译 —— 这次就当场抓到一处只有 macOS 路径才会踩到的编译错误（漏声明 `xt_release`）。但 **macOS 上的实际行为仍需在 Mac 上验证**（本仓库 CI 只跑 Windows）。

## v1.2.5

**修复**

- **音效/音乐流句柄改为槽位池 + 标记整数(issue #44)**:`XT_LoadSound`/`XT_LoadMusicStream` 原先把 `calloc` 出来的 `Sound*`/`Music*` **裸 C 指针**当句柄返回——它 LSB=0 且 >4096,玄铁侧 ARC 会按"堆对象"校验 magic,读到的却是 raylib 结构体,于是**加载任意 wav 就误报「堆损坏或非法指针访问」并退出**。现与纹理/字体统一为 `XT_FROM_INT(槽号+1)`,**0 表示失败**(加载失败/文件缺失/槽位耗尽);全部音效/音乐流操作(播放、更新、停止、卸载)同步改为按句柄取值。Windows 与 macOS 同源,两边都已验证。
- **纹理解码失败不再返回假句柄(issue #44 评论)**:旧实现解码失败后仍标记占用并返回非 0 句柄,调用方用 `!= 0` 判断会误判成功,之后拿着"空纹理"绘制(表现为句柄非 0、尺寸为 0)。现解码失败(`tex.id == 0`)或文件缺失一律返回 `0` 且不占槽位。
- 文件头补「外函返回值编码约定」说明:不得返回裸 C 指针;资源句柄一律"槽位池 + `XT_FROM_INT(槽号+1)`",0 为失败。

**已知限制**

- 随包 raylib 静态库**未编译 JPG/TGA 解码器**:`.jpg`/`.tga` 加载报 `IMAGE: Data format not supported`(实测:不同来源基线 JPEG、灰度 JPEG、TGA 全部失败;png/bmp/gif 正常)。需要这些格式请先转 PNG。文档已在 `GUIDE/09` 标注支持格式。

## v1.2.0

**新增**

- **SVG 纹理**:`加载SVG纹理("路径.svg", 宽, 高)`——内置 nanosvg(单头库)光栅化;宽/高传 0 取 SVG 固有尺寸,否则等比缩放进 宽×高。宽字符读文件,中文路径安全。
- **圆角渐变纹理生成器**:`生成渐变纹理(宽, 高, r1,g1,b1,a1, r2,g2,b2,a2, 方向, 圆角, 羽化)`——双色线性渐变(0=横 1=竖)+ 圆角矩形 SDF 覆盖度(天然抗锯齿)+ 边缘羽化;8 槽参数缓存,每帧同参调用零重复生成,缓存满轮转淘汰。
- **纹理工具**:`量纹理宽`/`量纹理高`/`绘纹理区`(整图缩放到指定矩形绘制,UI 图标适配用)。
- **GDI 字距**:`绘字体文字`/`量字体文字` 的 spacing 对系统字体生效:绘制侧加在每字符步进上,测量侧加 spacing×(字符数-1),两侧一致,光标定位不漂移。

**变更**

- 窗口初始化默认开启 **MSAA 4x**(FLAG_MSAA_4X_HINT):圆角矩形/斜边/旋转纹理边缘平滑;GPU 取不到多样本帧缓冲时自动降级,不影响功能。
- 纹理句柄池 16 → 32(UI 图标缓存、渐变纹理缓存、用户纹理共存)。

**修复**

- `截图` 绝对路径(含 `G:/...` 正斜杠写法)被 raylib `TakeScreenshot` 误拼工作目录导致写文件失败;改走 `LoadImageFromScreen`+`ExportImage` 直出,相对路径行为不变。

## v1.1.0

**新增**

- **GDI 系统字体渲染**:`加载系统字体("微软雅黑", 字号)`——Windows 系统级光栅化(`GetGlyphOutlineW` 65 级灰阶),视觉效果与系统应用同级;**无需 ttf 文件**(直接用系统字体名),生僻字由系统字体引擎自动回落;按需栅格化 + 2048² 动态图集缓存(4px 间隔防双线性渗色),多字号独立缓存,启动零成本。句柄与 `绘字体文字`/`量字体文字`/`释字体` 完全通用(句柄 ≥100 自动分派)。
- **截图**:`截图("文件名.png")`——当前帧缓冲导出 PNG(须在 `结束绘图()` 之后调用;路径为相对路径,raylib 会拼到工作目录前)。渲染调试与自动化验收用。

**变更**

- 字体渲染回滚至原始位图管线(移除 v1.0.1 引入的 SDF 距离场与 .xtfc 磁盘缓存):无平滑预处理的原始光栅化,2 万全 CJK 字形构建成本大幅降低。需要系统级观感的中文界面请改用 `加载系统字体`。

**修复**

- GDI 灰阶模式常量误用(`GGO_GRAY8_BITMAP` 应为 6,曾误写 5=GRAY4 的 17 级粗量化)导致字形粗大、边缘台阶感。
