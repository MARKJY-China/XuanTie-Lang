# 字符流 接口设计文档

> 版本 0.1.0 · 2026-11-17 · 萃取自 music-sort 真机 TUI
> 设计总则：**薄层、中立、坑优先**——只管字符进出，不做任何"帮应用搭界面"的
> 事；接口形态由踩坑记录倒逼而来，每条语义都标注对应的真机教训。

## 0. 设计原则

1. **薄层**：库只做"字节 ↔ 事件"与"序列原语"，界面布局/配色方案/交互逻辑
   一概不管（一人一个样）。
2. **中立**：解析器不知道应用的语义。孤 ESC 报键 27 而不是"退出"——退出键
   是应用的约定（music-sort 约定只认 Ctrl+C），库不替应用做决定。
3. **坑即文档**：每个函数头注释里的"为什么"都比"是什么"长；完整坑记录见
   支持矩阵.md（随库走）。
4. **双模式等价**：轮询/阻塞两种模式功能等价，接口统一，只是心跳节奏不同。

## 1. 接口一览

| 接口 | 签名 | 返回 |
|---|---|---|
| 进原始模式 | `公 函 进原始模式()` | 真=轮询模式 / 假=阻塞模式 |
| 恢复终端 | `公 函 恢复终端()` | —（必须与 进原始模式 配对） |
| 取事件 | `公 函 取事件()` | 事件字典（见 §2） |
| 取转义 | `公 函 取转义()` | ESC 字节串 |
| 前色 / 背色 | `公 函 前色(n)` / `背色(n)` | 256 色 SGR 序列 |

内部私有：`取键节`（逐字节）、`解析SGR鼠标`、`解析X10鼠标`、`SGR事件`。

## 2. 事件模型

`取事件()` 每次返回一条事件（字典）：

| 类型 | 字段 | 语义 |
|---|---|---|
| `"无"` | — | 空转心跳。轮询模式每拍约 100ms——**这是空闲自动刷新的节拍来源**（music-sort 分秒/进度条靠它走，2026-11-08 落地） |
| `"断"` | — | 终端不可用（句柄打不开或 EOF）。应用应退出并调 恢复终端 |
| `"键"` | `码` | ASCII 码。方向键映射 1001上/1002下/1003左/1004右（避开字面 A/B/C/D 的 ASCII 65-68）；孤 ESC 报 27 |
| `"鼠标"` | `按钮` `列` `行` `动作` | 列/行 **0 起**（终端原生 1 起，库内已减 1）；动作 = 按下/释放/上滚/下滚；滚轮事件 `按钮` 为 64/65 |

键码扩展约定：1000+ 区间保留给非 ASCII 键（功能键等，将来按需追加）。

## 3. 模式管理细节

**进原始模式** 做四件事：探测 `/dev/tty` 可开性 → `stty raw -echo min 0 time 1`
（轮询）或 `stty raw -echo`（阻塞回退）→ 进备用屏 `?1049h`+清屏+隐藏光标 `?25l`
→ 开鼠标 `?1000h ?1006h`。

- `min 0 time 1` 是轮询模式的命根：每次 read 自带 100ms 超时，读即心跳。
- 返回值假（无控制终端环境，如部分 CI/管道场景）不阻断使用——功能等价，
  只是应用应停用"空闲自动刷新"类特性。

**恢复终端**：`stty sane` + 关鼠标 + 显示光标 + 出备用屏。忘调用 = 用户终端
残留 raw 模式变哑（真机教训）。

## 4. 逐字节读的关键机制（坑最密集处）

`取键节`（私有）的句柄策略——**常驻 + 空读即弃**：

- **为什么常驻**：`文件.打开` 是 stdio 缓冲流。每次新开句柄读 1 字节，首次读
  会把输入队列里**整段多字节序列**（鼠标 SGR 11 字节、方向键 3 字节）预读进
  FILE 缓冲，读完 1 字节即关闭 → 其余字节全丢，事件只剩孤 ESC。表现为
  "单字节键（m/Ctrl+C）正常、鼠标方向键全灭"，且测试套件曾因此假通过
  （断言被无关日志污染）。真机回归 2026-11-08，字节级日志实锤。
- **为什么空读即弃**：空读（VTIME 超时）可能在句柄上留下**粘性 EOF** 标志，
  旧句柄永远读空。读空即关闭弃之、下次新开，兼得两头。
- **语义契约**：`句柄.读字节(n)` 超时空读返回**"成功且空串"**（`r.成功 == 真`
  且 `r.值 == ""`），不是失败。只判 `.成功` 的实现会永不关句柄、卡死全部
  输入——这是真机实撞出来的坑，也是本库最关键的运行时依赖（见 §6）。

## 5. 转义原语与配色约定

- `取转义()`：ESC 经字节缓冲构造（字符串字面量写不出 0x1B）。
- `前色(n)`/`背色(n)`：256 色 SGR。**拼接顺序铁律**：纯文本先经宽度函数定宽，
  色码只在拼接时包裹——色码不占显示列，但会被宽度计算当普通字符计宽
  （真机踩坑：头栏 10 格进度条虚增 10 列）。
- 本库**不含**显示宽/裁宽/补齐宽：东亚宽度是数万行码点表，现有实现是近似
  子集（`—`/`♪` 属 East Asian Ambiguous，终端间不一致），将来必然要改，
  不符合"稳固无可改"的进库标准。应用自备宽度函数，或在别处单独立项。

## 6. 运行时依赖契约（C1–C4，希望得到官方确认）

本库依赖以下四个运行时行为：今天实测是对的，但官方文档未记载——运行时升级
若行为变化，本库会静默失效。希望随 PR 一并写成白纸黑字的承诺（登记形式由
作者定）：

| # | 契约 | 版本依据 | 破坏后果 |
|---|---|---|---|
| C1 | `句柄.读字节(n)` 在 VTIME 超时空读时返回**成功且空串**（Result.成功=真、值=""） | 26.11.3 实测 | 库卡死全部输入（粘性 EOF 不释放） |
| C2 | `文件.打开(路径, "读")`：模式为中文「读」；返回 Result 须 `.值` 后调句柄方法 | 26.11.3 实测 | 库打不开 tty |
| C3 | `时.毫秒()`/`时.微秒()` 可用作唯一命名素材 | 26.11.3 实测 | （库本体不用，示例/应用用） |
| C4 | Unix 环境：`stty` 命令存在、`/dev/tty` 设备文件、POSIX 信号语义的 Ctrl+C | 平台约定 | Windows 无——Windows 化需第二条读键路径（支持矩阵 §6） |

已知**不依赖**：`选()`/通道/异步任务——主线程泵送 gate 未解（无限任务卡死
主线程，源码级证实，立案 #142；另 `收` 超时参数被整体丢弃见 #143），
本库读键走 tty 轮询绕开调度器，反而是这个 gate 的
workaround 产物。

## 7. 已知限制与实验性

- **X10 鼠标解析未真机验证**：解析代码在（ESC [ M + 3 原始字节），但所有
  测试与真机均走 SGR 1006。标记为实验性，待补 pty 注入用例后转正。
- **其他 CSI 序列**：报终字节给应用，不解析（如 `ESC[2~` 插入键类）。
- **Windows 未实现**：需 ConPTY 第二条读键路径（支持矩阵 §6 方向备忘）。
- **粘贴多行**：未启用括号粘贴（2004h），换行会被当回车——应用若做输入框
  需自行处理或将来库内加 2004h 开关（已知雷区，支持矩阵 §9）。

## 8. 验证方式

- `示例.xt` + `测试/示例驱动.py`：pty 驱动全事件形态（普通键/方向键/SGR
  点击/滚轮/孤 ESC/退出恢复），8 项断言全过（2026-11-17）。
- 集成级回归（14 项套件 + 三专项）在 music-sort 应用仓库：本库代码先在
  应用内真机验证，再萃取成库，`字符流.xt` 每个函数都能在应用源码中找到
  对应的验证记录。
