# 字符流 接口设计文档

> 版本 v0.1.0 · 2026-11-18 · 萃取自 music-sort 真机 TUI
> 平台：Unix（tty/stty）与 Windows（ReadConsoleInputW 控制台事件后端）双后端，
> 公开接口一致；分支点与平台差异见 §3、§4、§6。
> 设计总则：**薄层、中立、坑优先**——只管字符进出，不做任何"帮应用搭界面"的
> 事；接口形态由踩坑记录倒逼而来，每条语义都标注对应的真机教训。

## 0. 设计原则

1. **薄层**：库只做"字节 ↔ 事件"与"序列原语"，界面布局/配色方案/交互逻辑
   一概不管（一人一个样）。
2. **中立**：解析器不知道应用的语义。孤 ESC 报键 27 而不是"退出"——退出键
   是应用的约定（music-sort 约定只认 Ctrl+C），库不替应用做决定。
3. **坑即文档**：每个函数头注释里的"为什么"都比"是什么"长；完整坑记录见
   支持矩阵.md（随库走）。
4. **双模式等价**：轮询/阻塞两种模式功能等价，接口统一，只是心跳节奏不同。

## 1. 接口一览

| 接口 | 签名 | 返回 |
|---|---|---|
| 进原始模式 | `公 函 进原始模式()` | 真=轮询模式 / 假=阻塞模式 |
| 恢复终端 | `公 函 恢复终端()` | —（必须与 进原始模式 配对） |
| 取事件 | `公 函 取事件()` | 事件字典（见 §2） |
| 取转义 | `公 函 取转义()` | ESC 字节串 |
| 前色 / 背色 | `公 函 前色(n)` / `背色(n)` | 256 色 SGR 序列 |

内部私有：`取键节`（逐字节）、`解析SGR鼠标`、`解析X10鼠标`、`SGR事件`。

**平台口径**：以上公开接口在 Unix 与 Windows 上签名、返回值、事件形态完全一致；
平台差异（tty/stty 与 ReadConsoleInputW）封装在库内私有实现与运行时桥里，
应用代码不需要按平台改（见 §3–§4、§6）。

## 2. 事件模型

`取事件()` 每次返回一条事件（字典）：

| 类型 | 字段 | 语义 |
|---|---|---|
| `"无"` | — | 空转心跳。轮询模式每拍约 100ms——**这是空闲自动刷新的节拍来源**（music-sort 分秒/进度条靠它走，2026-11-08 落地）。Windows 分支同样每拍 100ms 返回一次心跳 |
| `"断"` | — | 终端不可用（句柄打不开、EOF、Windows 控制台不可用）。应用应退出并调 恢复终端 |
| `"键"` | `码` | ASCII 码。方向键映射 1001上/1002下/1003左/1004右（避开字面 A/B/C/D 的 ASCII 65-68）；孤 ESC 报 27 |
| `"鼠标"` | `按钮` `列` `行` `动作` | 列/行 **0 起**（终端原生 1 起，库内已减 1）；动作 = 按下/释放/上滚/下滚；滚轮事件 `按钮` 为 64/65 |

键码扩展约定：1000+ 区间保留给非 ASCII 键（功能键等，将来按需追加）。

**其他 CSI 序列**（Home/End/Insert/Delete/PgUp/PgDn/F1–F12 等）：解析器按 §7
既有规则只报**终字节**给应用（如 Home 报 72、Insert/Delete 与 F 键报 126）。
Windows 后端按同一套终端字节流注入（Home→`ESC[H`、F1→`ESC[11~` 等），两平台
行为一致——**本版不新增键码**。

## 3. 模式管理细节

**进原始模式** 按 `系统.操作系统类别()` 分两条后端路径，做同样三件事：进入
原始输入模式 → 进备用屏 `?1049h` + 清屏 + 隐藏光标 `?25l` → 开鼠标
`?1000h ?1006h`；返回值语义两平台一致。

**Unix 分支**：探测 `/dev/tty` 可开性 → `stty raw -echo min 0 time 1`（轮询）
或 `stty raw -echo`（阻塞回退）→ 输出进入序列。

**Windows 分支**（运行时 ReadConsoleInputW 事件后端，见 §6 C5）：运行时
`xt_tui_enter()` 把控制台输入模式设为
`ENABLE_EXTENDED_FLAGS|ENABLE_WINDOW_INPUT|ENABLE_MOUSE_INPUT`（去掉行缓冲/
回显/`ENABLE_PROCESSED_INPUT`，Ctrl+C 不再触发控制台信号）、输出追加
`ENABLE_VIRTUAL_TERMINAL_PROCESSING`；把 Console 事件翻译成与 Unix 相同的 VT
字节流后再喂给 §4 的同一解析器。`xt_tui_enter()` 返回非 0 → 轮询模式（返 真，
每拍 100ms 心跳）；返回 0（stdin 不是控制台/被重定向）→ 阻塞回退（返 假）：
库内 `是窗=假` 且 `tty轮询=假`，`取键节` 落 `xt_stdin_read_n(1)` 阻塞读
（EOF→空→"断"），与 Unix 无 ctty 回退同义。

- `min 0 time 1` 是 Unix 轮询模式的命根：每次 read 自带 100ms 超时，读即心跳。
- 返回值假（无控制终端环境，如部分 CI/管道场景）不阻断使用——功能等价，
  只是应用应停用"空闲自动刷新"类特性。

**恢复终端**：Unix 为 `stty sane` + 关鼠标 + 显示光标 + 出备用屏；Windows 为
**先输出恢复序列、再调 `xt_tui_leave()`**——顺序不能反：先关 VT 处理
（`xt_tui_leave`）会让后续 ESC 序列变成字面乱码，光标/备用屏状态退不出来。
`xt_tui_leave()` 内部先 `fflush(stdout)` 再还原输出模式（把序列真刷到控制台）。
两平台恢复时都关闭常驻 tty 句柄。忘调用 = 用户终端残留 raw/备用屏状态
（Unix 侧最坏是终端变哑，只能 blind 输入 reset 自救；真机教训）。

## 4. 逐字节读的关键机制（坑最密集处）

### 4.1 Unix 分支：句柄常驻 + 空读即弃

`取键节`（私有）的句柄策略——**常驻 + 空读即弃**：

- **为什么常驻**：`文件.打开` 是 stdio 缓冲流。每次新开句柄读 1 字节，首次读
  会把输入队列里**整段多字节序列**（鼠标 SGR 11 字节、方向键 3 字节）预读进
  FILE 缓冲，读完 1 字节即关闭 → 其余字节全丢，事件只剩孤 ESC。表现为
  "单字节键（m/Ctrl+C）正常、鼠标方向键全灭"，且测试套件曾因此假通过
  （断言被无关日志污染）。真机回归 2026-11-08，字节级日志实锤。
- **为什么空读即弃**：空读（VTIME 超时）可能在句柄上留下**粘性 EOF** 标志，
  旧句柄永远读空。读空即关闭弃之、下次新开，兼得两头。
- **语义契约（C1，只约束 Unix 分支）**：`句柄.读字节(n)` 超时空读返回
  **"成功且空串"**（`r.成功 == 真` 且 `r.值 == ""`），不是失败。只判
  `.成功` 的实现会永不关句柄、卡死全部输入——这是真机实撞出来的坑，也是
  本库最关键的运行时依赖（正式文档见 `GUIDE/关键字/文件.md`，库级回归见
  `测试/C1读字节超时.py`，§6）。
- 阻塞模式（无 ctty 回退）：`xt_stdin_read_n`，空=EOF，语义同旧版。

### 4.2 Windows 分支：运行时事件翻译

Windows 上 `tty句柄` 恒为 `空`，**不走** `文件.打开("/dev/tty")` / `句柄.读字节`
路径（C1 在 Windows 上不适用）。`取键节` 改调运行时桥 `xt_tui_read_n(100)`：
每拍最多等 100ms，每次恰好返回 0 或 1 字节（二进制安全、可含 NUL）——
`""`=本轮无事件（心跳）、单字节串=读到一字节 VT 字节流、`空`=控制台不可用。
运行时把 `ReadConsoleInputW` 的 KEY_EVENT/MOUSE_EVENT 翻译成与 Unix 完全相同的
VT/xterm 字节流（方向键 `ESC[A/B/C/D`、SGR 鼠标 `ESC[<b;x;yM/m`、滚轮
`b=64/65`、Ctrl 字符按原始字节发送、各功能键注入 `ESC[n~`），因此上游
`取事件`/SGR 解析器在 Windows 上原样复用，不需要第二套解析代码。

## 5. 转义原语与配色约定

- `取转义()`：ESC 经字节缓冲构造（字符串字面量写不出 0x1B）。
- `前色(n)`/`背色(n)`：256 色 SGR。**拼接顺序铁律**：纯文本先经宽度函数定宽，
  色码只在拼接时包裹——色码不占显示列，但会被宽度计算当普通字符计宽
  （真机踩坑：头栏 10 格进度条虚增 10 列）。
- 本库**不含**显示宽/裁宽/补齐宽：东亚宽度是数万行码点表，现有实现是近似
  子集（`—`/`♪` 属 East Asian Ambiguous，终端间不一致），将来必然要改，
  不符合"稳固无可改"的进库标准。应用自备宽度函数，或在别处单独立项。

## 6. 运行时依赖契约（C1–C5，已正式化）

本库依赖以下运行时行为。C1–C4 自 0.1.0 起写成白纸黑字的正式文档并配回归
（不再只是"实测如此"）；C5 是 Windows 分支新增的运行时桥契约，与库同版落地。

| # | 契约 | 正式文档 / 回归 | 破坏后果 |
|---|---|---|---|
| C1 | **Unix 分支**：`句柄.读字节(n)` 在 VTIME 超时空读时返回**成功且空串**（Result.成功=真、值=""） | `GUIDE/关键字/文件.md`「读字节」；`测试/C1读字节超时.py`（Unix CI 实跑） | 库卡死全部输入（粘性 EOF 不释放） |
| C2 | `文件.打开(路径, "读")`：模式为中文「读」；返回 Result 须 `.值` 后调句柄方法 | `GUIDE/关键字/文件.md`；C1 用例与 `测试/示例驱动.py` 均实际走该路径 | 库打不开 tty |
| C3 | `时.毫秒()`/`时.微秒()` 可用作唯一命名素材 | `GUIDE/关键字/时.md`（既有官方文档） | （库本体不用，示例/应用用） |
| C4 | **Unix 平台约定**：`stty` 命令存在、`/dev/tty` 设备文件、POSIX 信号语义的 Ctrl+C | `支持矩阵.md` §3/§4；`测试/示例驱动.py` 实际走 stty 进原始模式 | Unix 轮询读键失效（Windows 走 C5 第二条路径） |
| C5 | **Windows 分支运行时桥**：`系统.操作系统类别()` 返回 `"windows"`；`xt_tui_enter(): 整`（非 0=进原始模式成功）、`xt_tui_leave(): 空`、`xt_tui_read_n(超时: 整): 字`（`""`=心跳 / 单字节 / 空=终端不可用，每次恰好 0 或 1 字节）；非 Windows 平台提供安全 stub（enter 恒 0 / read_n 恒 `""` / leave no-op，Unix 链接无需 `#ifdef`） | `支持矩阵.md` §6；C 原型随 `runtime/xt_runtime.h` 发布；运行时 `ReadConsoleInputW` 后端与库同版落地 | 链接缺符号；事件节奏/键码漂移 |

C5 的 `恢复终端` 顺序契约（Windows）：**先输出恢复序列、再 `xt_tui_leave()`**，
反序会让 ESC 序列变字面乱码、退不出备用屏/光标状态；`xt_tui_leave()` 内部先
`fflush(stdout)` 再还原输出模式——这是实现期按正确性定的口径，文档与测试以此为据。

**C5 验证边界（按"声明=测过"）**：已过——runtime 在 Windows 目标与 Linux 目标
各 clang 编译 0 error（stub 符号导出）、`-jc --yange` 检查、`示例.xt` 实际链接
（exe 含三个 `xt_tui_*` 符号）、`-lib` 对象中三符号为 U（由主程序解析）、
白盒翻译探针 51 断言（方向/编辑/功能键、Ctrl 字符、UTF-8/代理对、SGR 按下释放
滚轮修饰、纯移动忽略、拖动中按下/释放仍上报、队列满丢最旧、`xt_tui_read_n`
逐字节且 NUL 安全）、无控制台/管道探针 8 断言（enter 返 0、read 返 空、leave
可重复、非法参数不崩、enter/read/leave 循环 3 次不崩）。**未测**：真实控制台
路径（enter=1、`ReadConsoleInputW`/`WaitForSingleObject` 心跳、控制台模式恢复）
——需在 Windows Terminal 真机人工验收，验收前 §3 支持口径不写"全功能"。

已知**不依赖**：`选()`/通道/异步任务。萃取期（运行时 26.11.3）主线程泵送 gate
未解（#142）且 `收` 超时参数被整体丢弃（#143），本库读键路径刻意不走调度器；
两 issue 已在 v1.0-rc.5 修复，但"读键不依赖调度器"仍是本库的设计选择——薄层
不该被调度器语义绑定，后续若要用 选/通道 作事件源需重新评估。历史上"绕开
调度器 workaround"的说法到此为止（可视为历史注记）。

## 7. 已知限制与实验性

- **X10 鼠标解析未真机验证**：解析代码在（ESC [ M + 3 原始字节），但所有
  测试与真机均走 SGR 1006。标记为实验性，待补 pty 注入用例后转正。
- **其他 CSI 序列**：只报终字节给应用，不解析（如 `ESC[2~` 插入键类；Windows
  后端按同样规则注入同样字节流 → 两平台一致）。
- **Windows 已知限制**：无 resize 事件（库无该 API）；Alt 组合不做 ESC 前缀
  （最终键码与 Unix 一致）；横向滚轮/双击语义不区分；粘贴多行仍未启用括号
  粘贴（见下一条）；stdin 必须是控制台，stdout 被重定向时 VT 渲染降级为原样
  字节（仅告警）；Ctrl+Break 不区分；Ctrl+C 按原始字节 3 上报，不触发控制台
  信号。支持终端/系统版本见 支持矩阵.md §3/§6。
- **粘贴多行**：未启用括号粘贴（2004h），换行会被当回车——应用若做输入框
  需自行处理或将来库内加 2004h 开关（已知雷区，支持矩阵 §9）。
